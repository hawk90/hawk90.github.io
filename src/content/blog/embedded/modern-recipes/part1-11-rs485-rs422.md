## 한 줄 요약

> **"RS-485는 두 선의 전압 차로 0과 1을 보내는 반이중 multi-drop 버스입니다."** TI 자료 기준으로 32 unit load, 이론상 최대 1200 m이고, 실제 길이는 bitrate와 함께 정해집니다. 종단·fail-safe bias·DE 전환 시점이 펌웨어와 보드가 함께 맞춰야 하는 부분입니다.

이 글의 전기 사양은 TI의 세 문서에서 가져왔습니다. RS-422과 RS-485의 차이는 SLLA070D *RS-422 and RS-485 Standards Overview and System Configurations*(2010), 종단·stub·fail-safe·부하 계산은 SLLA272D *The RS-485 Design Guide*(2021), 수신 임계값은 TI THVD1450 데이터시트(SLLSEY3E)입니다. Modbus RTU 규칙은 Modbus.org *MODBUS over serial line specification and implementation guide V1.02*(2006-12-20)입니다. TIA/EIA-485 원문은 대조하지 않았습니다.

## 어떤 상황에서 쓰나

- 공장 PLC와 sensor/actuator 통신 (Modbus RTU)
- PROFIBUS 계열 필드버스(THVD1450 Features는 5 V 전원에서 PROFIBUS 호환 차동 출력 2.1 V 이상을 적습니다)
- 노이즈가 많은 환경에서 보드와 보드를 수십~수백 m 거리로 잇는 시리얼

## 핵심 개념

### 1) RS-422 vs RS-485

SLLA070D Table 4의 비교입니다.

| 항목 | RS-422 | RS-485 |
| --- | --- | --- |
| driver / receiver 수 | driver 1개, receiver 10개 | 32 unit load(U.L.) |
| 이론상 최대 케이블 길이 | 1200 m | 1200 m |
| 최대 data rate | 10 Mbps | > 10 Mbps |
| common-mode 전압 | ±7 V | −7 ~ +12 V |
| driver 차동 출력 | 2 ≤ \|V_OD\| ≤ 10 V | 1.5 ≤ \|V_OD\| ≤ 5 V |
| driver 부하 | ≥ 100 Ω | ≥ 60 Ω |
| receiver 입력 저항 | 4 kΩ | 12 kΩ |
| receiver 감도 | ±200 mV | ±200 mV |

RS-422은 driver 하나가 여러 receiver에 보내는 구조이고, RS-485는 한 번에 driver 하나만 말한다는 전제(half-duplex) 아래 여러 driver가 같은 선을 씁니다(SLLA070D 2.2절). SLLA272D 3절은 RS-485도 두 쌍(4선)으로 full-duplex를 만들 수 있고, 한 쌍이면 송신과 수신이 시간을 나눠 쓰는 half-duplex라고 적습니다. 1 U.L.은 약 12 kΩ이고, 요즘 transceiver는 1/8 U.L.로 버스에 256개까지 붙일 수 있습니다(SLLA272D 8절, THVD1450도 1/8 U.L.).

길이와 속도는 서로 깎아 먹습니다. SLLA070D 2.1절은 RS-422에 대해 "data rate(bps) × 케이블 길이(m) ≤ 10^8"을 rule of thumb으로 들며, 500 m면 200 kbps를 넘지 말라고 적습니다. 1200 m를 다 쓰면 이 식으로 83.3 kbps입니다. RS-485에 대해서는 SLLA272D 9절이 10% 지터를 기준으로 그린 케이블 길이 대 data rate 곡선(Figure 9-1)을 제시합니다.

### 2) 차동 전압과 수신 임계값

driver가 D = H를 받으면 A를 high, B를 low로 구동하고, receiver는 V_ID = V_A − V_B로 판정합니다(THVD1450 Table 1·2). THVD1450 Table 2와 7.7절의 임계값은 다음과 같습니다(공통 모드 ±15 V 범위).

| V_ID = V_A − V_B | 수신 출력 R |
| --- | --- |
| V_ID > V_TH+ (max −20 mV) | H |
| V_TH− < V_ID < V_TH+ | 정해지지 않음 |
| V_ID < V_TH− (min −200 mV) | L |
| 버스 open·short·idle(종단된 상태) | H (fail-safe) |

V_TH+가 최대 −20 mV라는 것은 V_ID = 0 V, 즉 아무도 구동하지 않아 두 선이 같은 전압이어도 출력이 H라는 뜻입니다. 이런 내장 fail-safe 덕분에 UART idle(1)이 그대로 유지됩니다. 다만 SLLA272D 7절은 이런 내장 fail-safe의 최악 noise margin이 10 mV에 불과해, 잡음이 큰 환경에서는 외부 fail-safe 회로가 필요하다고 적습니다.

### 3) Bus 구조와 종단

![RS-485 Multi-drop Bus](/images/blog/modern-recipes/diagrams/part1-11-rs485-bus.svg)

SLLA272D 6절은 RS-485가 특성 임피던스 120 Ω 케이블을 권장하므로 양 끝을 120 Ω으로 종단한다고 적습니다. Modbus V1.02 3.4.5절도 버스 양 끝 근처에 line termination을 두고, 한 쌍에 둘을 넘게 달지 말며, 분기 케이블에는 달지 말라고 합니다. 같은 절은 150 Ω(0.5 W) 저항, 또는 bias를 걸 때는 1 nF 직렬 커패시터 + 120 Ω을 예로 듭니다.

stub(트렁크에서 transceiver까지의 분기)은 driver rise time의 1/10보다 전기적으로 짧아야 합니다. SLLA272D 식 (1)은 L_stub ≤ t_r / 10 × v × c이고, 같은 문서 Table 6-1은 rise time 100 ns(SN65HVD12, 1 Mbps)에서 7 ft, 500 ns(SN65HVD3082E)에서 38 ft를 줍니다. 100 ns를 식에 넣어 다시 계산하면 7.6 ft로 표와 맞습니다(v = 0.78, c = 9.8 × 10^8 ft/s).

### 4) Fail-safe biasing

모든 driver가 꺼진 idle 버스는 두 선이 종단 저항으로 묶여 V_ID ≈ 0 V가 됩니다. 외부 fail-safe는 한쪽 선을 전원으로, 다른 쪽을 GND로 당기는 저항 쌍으로 V_ID를 receiver 임계값 위로 올려 둡니다.

![Fail-safe Biasing — 양 끝 120 Ω 종단과 523 Ω bias 저항 쌍](/images/blog/modern-recipes/diagrams/part1-11-fail-safe-bias.svg)

SLLA272D 식 (2)는 bias 저항을 R_B = V_BUS,min / (V_AB × (1/375 + 4/Z0))로 줍니다. 375 Ω은 32 U.L.의 병렬 저항, 4/Z0는 양 끝 120 Ω 두 개(병렬 60 Ω)를 나타냅니다. V_AB는 receiver 임계값 200 mV에 측정한 차동 잡음을 더한 값입니다. 문서 예시대로 V_BUS,min = 4.75 V, V_AB = 0.25 V, Z0 = 120 Ω을 넣으면 528 Ω이고, 문서는 523 Ω 두 개를 씁니다. Modbus V1.02 3.4.6절은 bias가 필요하면 버스 전체에 한 곳(보통 master)에만 450~650 Ω 저항 쌍을 두고, 그만큼 버스에 붙일 수 있는 장치 수가 4개 줄어든다고 적습니다.

5 V 전원에서 bias 저항과 노드 수를 바꿔 V_AB를 계산했습니다. 부하는 양 끝 120 Ω과 노드 입력 저항(1 U.L. = 12 kΩ)의 병렬입니다.

```text
Vbus 5 V, RB 450 ohm, 2x120 ohm term, 2 nodes x 1.0 UL (6000 ohm): VAB = 310 mV
Vbus 5 V, RB 523 ohm, 2x120 ohm term, 2 nodes x 1.0 UL (6000 ohm): VAB = 269 mV
Vbus 5 V, RB 650 ohm, 2x120 ohm term, 2 nodes x 1.0 UL (6000 ohm): VAB = 218 mV
Vbus 5 V, RB 450 ohm, 2x120 ohm term, 32 nodes x 1.0 UL (375 ohm): VAB = 272 mV
Vbus 5 V, RB 523 ohm, 2x120 ohm term, 32 nodes x 1.0 UL (375 ohm): VAB = 236 mV
Vbus 5 V, RB 650 ohm, 2x120 ohm term, 32 nodes x 1.0 UL (375 ohm): VAB = 191 mV
```

32 U.L. 버스에서 650 Ω은 191 mV로 200 mV 임계값에 못 미칩니다. Modbus 범위의 위쪽 끝은 노드가 적을 때만 RS-485 감도 200 mV를 넘깁니다. THVD1450처럼 V_TH+가 −20 mV인 receiver는 이 정도 bias로도 idle을 1로 읽지만, 버스에 V_ID = 0 V에서 출력이 정해지지 않는 ±200 mV 감도의 receiver가 하나라도 있으면 그 노드 기준으로 계산합니다. SLLA272D 8절에 따르면 fail-safe bias는 버스 부하를 최대 20 U.L. 더하므로, 1/8 U.L. transceiver를 써도 노드 수는 (32 − 20) / (1/8) = 96개로 줄어듭니다.

### 5) Half-duplex와 DE 전환 시점

한 쌍을 나눠 쓰므로 송신 노드는 DE(driver enable)를 켜고 보낸 뒤, 마지막 비트가 선을 떠난 다음 DE를 꺼서 버스를 놓아야 합니다. STM32 USART에는 TDR이 비었다는 `TXE`와 시프트 레지스터의 마지막 stop bit까지 나갔다는 `TC`가 따로 있습니다. `TXE`에서 DE를 끄면 마지막 바이트가 아직 시프트되는 중이라 잘립니다. 그래서 아래 코드는 `TC`를 기다립니다.

## 코드 / 실제 사용 예 — Modbus RTU 요청 보내기

Modbus RTU에서 한 바이트는 11비트입니다(start 1, data 8, parity 1, stop 1; parity가 없으면 stop 2). 프레임 사이는 3.5 문자 시간(t3.5) 이상 비우고, 프레임 안에서 문자 사이가 1.5 문자 시간(t1.5)을 넘으면 수신 측은 그 프레임을 버립니다. 19200 bps 이하에서는 이 두 타이머를 그대로 지키고, 그보다 빠르면 t1.5 = 750 µs, t3.5 = 1.750 ms 고정값을 권장합니다(Modbus V1.02 2.5.1, 2.5.1.1절). 9600 bps면 한 문자가 11 / 9600 = 1.146 ms, t3.5 = 4.01 ms, t1.5 = 1.72 ms입니다.

CRC는 0xFFFF로 시작해, 바이트마다 하위 바이트에 XOR하고 오른쪽으로 8번 밀며 밀려난 비트가 1이면 0xA001을 XOR합니다. 결과는 하위 바이트를 먼저 붙입니다(Modbus V1.02 2.5.1.2절, 부록 6.2.2). 아래는 STM32L4 USART로 요청 하나를 보내는 코드입니다.

```c
#include "stm32l4xx.h"

#define DE_RE_PIN 5                      /* PA5 -> transceiver DE and /RE */

/* Modbus RTU CRC-16: preset 0xFFFF, poly 0xA001, LSB-first (Modbus serial V1.02 6.2.2) */
uint16_t modbus_crc16(const uint8_t *p, int n) {
    uint16_t crc = 0xFFFF;
    while (n--) {
        crc ^= *p++;
        for (int i = 0; i < 8; i++)
            crc = (crc & 1) ? (crc >> 1) ^ 0xA001 : crc >> 1;
    }
    return crc;
}

void modbus_send(const uint8_t *pdu, int len) {
    uint16_t crc = modbus_crc16(pdu, len);
    GPIOA->BSRR = (1u << DE_RE_PIN);                 /* driver on, receiver off */
    for (int i = 0; i < len + 2; i++) {
        uint8_t b = (i < len) ? pdu[i] : (i == len ? (uint8_t)crc : (uint8_t)(crc >> 8));
        while (!(USART1->ISR & USART_ISR_TXE)) { }   /* TDR empty */
        USART1->TDR = b;
    }
    while (!(USART1->ISR & USART_ISR_TC)) { }        /* last stop bit has left */
    GPIOA->BSRR = (1u << (DE_RE_PIN + 16));          /* back to receive */
}
```

QEMU 11.1.3의 STM32L475 머신(`b-l475e-iot01a`)은 USART1과 GPIO를 모델링하므로, 이 코드를 실제로 돌려 버스로 나가는 바이트를 파일로 받았습니다. `main()`은 먼저 부록의 예제 프레임 `02 07`의 CRC를 계산하고, 슬레이브 1의 holding register 0번부터 10개를 읽는 요청(`01 03 00 00 00 0A`)을 보냅니다. 빌드에는 1-03과 같은 semihosting startup·링커 스크립트를 썼습니다.

```bash
arm-none-eabi-gcc -mcpu=cortex-m4 -mthumb -O1 -ffreestanding -nostdlib -DSTM32L475xx \
  -I cmsis_device_l4/Include -I CMSIS_5/CMSIS/Core/Include -Wall \
  -T link-l4.ld startup.c sh.c modbus.c main.c -lgcc -o mb.elf
qemu-system-arm -M b-l475e-iot01a -nographic -monitor none -serial file:uart.bin \
  -semihosting-config enable=on,target=native -kernel mb.elf
xxd uart.bin
```

```text
CRC(02 07) = 0x1241 -> sent as 41 12
DE before=0
DE after=0
00000000: 0103 0000 000a c5cd                      ........
```

부록 6.2.2의 예제는 프레임 `02 07`의 CRC를 하위 0x41, 상위 0x12로 적고, 위 계산이 같은 값을 냅니다. 요청 프레임의 CRC `C5 CD`는 libmodbus v3.1.11의 표 기반 `crc16()`(`src/modbus-rtu.c` 116~130행)을 호스트에서 따로 돌려 얻은 0xCDC5(전송 순서 C5, CD)와도 같습니다. DE 핀(PA5)은 송신 전과 `TC`를 확인한 뒤 모두 0입니다. QEMU의 USART 모델은 비트 시간을 흉내 내지 않으므로, 이 실행은 프레임 내용과 CRC 순서를 확인할 뿐 DE를 내리는 시점의 타이밍까지 보여 주지는 않습니다.

응답은 t3.5 동안 바이트가 없으면 프레임이 끝난 것으로 봅니다. 마이크로초 카운터는 보드마다 다르므로 `now_us()`로 빼 두었습니다. 같은 헤더로 경고 없이 빌드되고, 실행은 하지 않았습니다.

```c
#include "stm32l4xx.h"

extern uint32_t now_us(void);            /* free-running microsecond counter (board-specific) */

/* Receive one RTU frame: a gap of t3.5 after the last byte ends the frame.
   9600 baud, 11-bit characters: t3.5 = 3.5 * 11 / 9600 s = 4010 us. */
int modbus_receive(uint8_t *buf, int max, uint32_t t35_us) {
    int n = 0;
    uint32_t last = now_us();
    while ((uint32_t)(now_us() - last) < t35_us) {
        if (USART1->ISR & USART_ISR_RXNE) {
            uint8_t b = (uint8_t)USART1->RDR;
            if (n < max) buf[n++] = b;
            last = now_us();
        }
    }
    return n;
}
```

이 루프는 t1.5 위반(프레임 중간의 긴 공백)을 따로 검사하지 않습니다. 사양대로 하려면 바이트 사이 간격이 t1.5를 넘었는지도 기록해 그 프레임을 버립니다.

## 자주 보는 함정

> ⚠️ Fail-safe bias 없이 ±200 mV receiver가 섞인 버스

위 표처럼 V_ID = 0 V에서 출력이 정해지지 않는 receiver는 idle 버스에서 아무 값이나 냅니다. UART가 그 값을 start bit로 읽으면 송신이 없는데도 garbage 바이트가 들어옵니다. bias 저항은 버스의 가장 둔감한 receiver를 기준으로 SLLA272D 식 (2)로 고르고, 노드 수가 늘어날수록 V_AB가 줄어드는 것도 계산에 넣습니다.

> ⚠️ `TXE`에서 DE를 내림

`TXE`는 TDR이 비었다는 뜻일 뿐, 마지막 바이트는 아직 시프트 레지스터에서 나가는 중입니다. `TC`를 기다린 뒤 DE를 내립니다.

> ⚠️ 중간 노드 종단

종단이 셋이면 버스 부하가 바뀝니다. 양 끝 120 Ω 두 개와 32 U.L.(375 Ω)의 병렬은 51.7 Ω인데, 중간에 120 Ω이 하나 더 붙으면 36.1 Ω이 됩니다. THVD1450 7.7절은 차동 출력 |V_OD|를 54 Ω 부하에서 최소 1.5 V로 보장하므로, 그보다 무거운 부하에서의 출력은 데이터시트가 보장하지 않습니다. Modbus V1.02도 한 쌍에 종단을 둘 넘게 두지 말라고 적습니다.

> ⚠️ GND 기준 없이 두 노드를 연결

차동이어도 각 선의 전압은 receiver의 common-mode 범위 안에 있어야 합니다. RS-485는 −7 ~ +12 V(SLLA070D Table 4), THVD1450은 ±15 V입니다. 두 노드의 GND 전위차가 이 범위를 넘을 수 있으면 공통 기준선을 함께 배선하거나 절연 transceiver를 씁니다.

> ⚠️ Address 충돌(Modbus)

같은 slave 주소를 두 노드에 설정하면 두 노드가 동시에 DE를 켜고 응답합니다. 두 driver가 반대 레벨을 구동하는 순간이 생기고, master는 CRC가 맞지 않는 프레임을 받습니다.

## 정리

- RS-485는 32 U.L.·이론상 1200 m(SLLA070D)이고, 길이와 속도는 함께 정해집니다. RS-422 rule of thumb은 bps × m ≤ 10^8입니다.
- THVD1450 같은 요즘 receiver는 V_TH+ ≤ −20 mV라 idle에서 1을 내지만, 최악 noise margin이 작아 외부 bias를 함께 씁니다(SLLA272D).
- 양 끝만 120 Ω 종단하고, bias는 버스에 한 곳만 둡니다. bias 저항은 노드 수까지 넣어 계산합니다(32 U.L.에서 650 Ω은 191 mV).
- DE는 `TC` 뒤에 내립니다.
- Modbus RTU CRC는 0xFFFF·0xA001·하위 바이트 먼저이고, QEMU에서 보낸 `01 03 00 00 00 0A C5 CD`가 사양 예제와 libmodbus 구현 모두와 맞습니다.
