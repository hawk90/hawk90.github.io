## 한 줄 요약

> **"USB device를 만드는 일의 대부분은 descriptor를 쓰는 일입니다."** control transfer, enumeration, endpoint FIFO는 TinyUSB 같은 stack이 맡고, 애플리케이션은 자신이 어떤 device인지 descriptor로 적고 class API로 data를 주고받습니다.

## 어떤 상황에서 쓰나

보드를 PC에 USB로 꽂아 serial 콘솔처럼 쓰고 싶을 때 CDC ACM class를 씁니다. Linux의 `cdc_acm` driver가 이 class를 받아 `/dev/ttyACM*`를 만듭니다.

이 글은 STM32F407의 OTG_FS로 받은 byte를 그대로 돌려주는 CDC echo device를 TinyUSB 0.18.0으로 만듭니다. 세 파일(`tusb_config.h`, `usb_descriptors.c`, `main.c`)과 빌드 명령을 그대로 옮기면 같은 크기의 ELF가 나옵니다. descriptor byte는 host에서 같은 파일을 컴파일해 풀었습니다. 실제 보드를 PC에 꽂아 enumeration한 결과는 없습니다. QEMU에는 STM32의 OTG_FS model이 없습니다.

## 핵심 개념

### STM32F407 OTG_FS

STM32F407 datasheet(DS8626 Rev 4) 2.2.30절과 Table 58에서 이 글에 필요한 것입니다.

| 항목 | 값 |
|---|---|
| peripheral | "USB OTG full-speed device/host/OTG peripheral with integrated transceivers", USB 2.0 준수 |
| clock | "requires a dedicated 48 MHz clock that is generated by a PLL connected to the HSE oscillator" |
| endpoint | "4 bidirectional endpoints" |
| FIFO | "Combined Rx and Tx FIFO size of 320 × 35 bits" |
| 핀 | PA11 = DM, PA12 = DP (AF10) |
| DP pull-up (RPU, PA12) | 1.5 / 1.8 / 2.1 kΩ (min / typ / max), chip 내부 |
| USB 동작 전압 | VDD 3.0 ~ 3.6 V |

48 MHz는 [4-04](/blog/embedded/modern-recipes/part4-04-clock-setup)의 PLL 설정(HSE 8 MHz, M = 8, N = 336, Q = 7 → 336 / 7 = 48 MHz)이 이미 만듭니다. DP pull-up이 chip 안에 있으므로 외부 1.5 kΩ는 달지 않습니다. TinyUSB는 `dcd_connect()`에서 `DCTL`의 SDIS bit를 지워 이 pull-up을 켜고, host는 DP가 올라간 것을 보고 full-speed device가 붙었다고 판단합니다.

### Descriptor

enumeration에서 host는 device descriptor, configuration descriptor, string descriptor를 차례로 GET_DESCRIPTOR로 읽고, 그 안의 class code로 driver를 고릅니다. 아래 `usb_descriptors.c`가 만드는 byte를 host에서 풀면 이렇습니다(다음 절의 실행 결과).

| descriptor | 이 글의 값 | 뜻 |
|---|---|---|
| Device | class 0xEF / subclass 0x02 / protocol 0x01 | Miscellaneous + IAD: interface들을 묶는 IAD가 있다는 표시 |
| Device | VID 0xCAFE, PID 0x4001 | TinyUSB 예제가 쓰는 값. 시험 전용 |
| Configuration | wTotalLength 75, 2 interfaces, bmAttributes 0x80, bMaxPower 0x32 | 75 = `TUD_CONFIG_DESC_LEN`(9) + `TUD_CDC_DESC_LEN`(66), bMaxPower는 2 mA 단위라 100 mA |
| IAD (type 0x0B) | interface 0부터 2개, class 0x02 | CDC 두 interface를 한 기능으로 묶음 |
| Interface 0 | class 0x02 (CDC), subclass 0x02 (ACM), endpoint 1개 | 제어 interface |
| Endpoint 0x81 | interrupt, 8 byte, interval 16 | 상태 알림 |
| Interface 1 | class 0x0A (CDC Data), endpoint 2개 | data interface |
| Endpoint 0x02 / 0x82 | bulk, 64 byte | data OUT / IN |

`TUD_CONFIG_DESCRIPTOR()`는 bmAttributes에 `TU_BIT(7) | _attribute`를 쓰고 bMaxPower에 `(_power_ma)/2`를 쓰므로, 인자 0x00·100이 0x80·0x32가 됩니다. class code는 TinyUSB `tusb_types.h`의 `TUSB_CLASS_CDC = 2`, `TUSB_CLASS_CDC_DATA = 10`, `TUSB_CLASS_MISC = 0xEF`입니다.

VID는 USB-IF가 할당하는 값입니다. 0xCAFE는 TinyUSB 예제의 값이라 제품에 쓰지 않습니다.

## 코드 예제

### 1. `tusb_config.h`

```c
/* tusb_config.h */
#ifndef TUSB_CONFIG_H
#define TUSB_CONFIG_H

#define CFG_TUSB_MCU             OPT_MCU_STM32F4
#define CFG_TUSB_OS              OPT_OS_NONE
#define CFG_TUD_ENABLED          1
#define CFG_TUD_MAX_SPEED        OPT_MODE_FULL_SPEED
#define CFG_TUD_ENDPOINT0_SIZE   64

#define CFG_TUD_CDC              1
#define CFG_TUD_CDC_RX_BUFSIZE   64
#define CFG_TUD_CDC_TX_BUFSIZE   64
#define CFG_TUD_CDC_EP_BUFSIZE   64

#endif
```

`CFG_TUSB_MCU = OPT_MCU_STM32F4`가 TinyUSB에 Synopsys DWC2 core driver(`dcd_dwc2.c`)를 고르게 합니다. RTOS 없이(`OPT_OS_NONE`) 돌리므로 TinyUSB가 시간을 물을 `tusb_time_millis_api()`를 `main.c`가 제공합니다.

### 2. `usb_descriptors.c`

```c
/* usb_descriptors.c */
#include <string.h>
#include "tusb.h"

static tusb_desc_device_t const desc_device = {
    .bLength            = sizeof(tusb_desc_device_t),
    .bDescriptorType    = TUSB_DESC_DEVICE,
    .bcdUSB             = 0x0200,
    .bDeviceClass       = TUSB_CLASS_MISC,      // CDC uses two interfaces:
    .bDeviceSubClass    = MISC_SUBCLASS_COMMON, // group them with an IAD
    .bDeviceProtocol    = MISC_PROTOCOL_IAD,
    .bMaxPacketSize0    = CFG_TUD_ENDPOINT0_SIZE,
    .idVendor           = 0xCafe,               // TinyUSB example VID, test only
    .idProduct          = 0x4001,
    .bcdDevice          = 0x0100,
    .iManufacturer      = 1,
    .iProduct           = 2,
    .iSerialNumber      = 3,
    .bNumConfigurations = 1,
};

enum { ITF_CDC_CTRL, ITF_CDC_DATA, ITF_TOTAL };
#define CONFIG_TOTAL_LEN (TUD_CONFIG_DESC_LEN + TUD_CDC_DESC_LEN)

static uint8_t const desc_configuration[] = {
    // config 1, interfaces, string 0, total length, attributes, 100 mA
    TUD_CONFIG_DESCRIPTOR(1, ITF_TOTAL, 0, CONFIG_TOTAL_LEN, 0x00, 100),
    // CDC: interface 0, string 4, notification EP 0x81 (8 B),
    //      data OUT 0x02, data IN 0x82, 64 B
    TUD_CDC_DESCRIPTOR(ITF_CDC_CTRL, 4, 0x81, 8, 0x02, 0x82, 64),
};

uint8_t const *tud_descriptor_device_cb(void) {
    return (uint8_t const *)&desc_device;
}

uint8_t const *tud_descriptor_configuration_cb(uint8_t index) {
    (void)index;
    return desc_configuration;
}

static char const *const strings[] = {
    NULL,               // 0: language ID, handled below
    "Example Maker",    // 1: manufacturer
    "CDC echo",         // 2: product
    "0001",             // 3: serial
    "CDC",              // 4: CDC interface
};

static uint16_t desc_str[33];

uint16_t const *tud_descriptor_string_cb(uint8_t index, uint16_t langid) {
    (void)langid;
    size_t n;
    if (index == 0) {
        desc_str[1] = 0x0409;                   // English (United States)
        n = 1;
    } else {
        if (index >= sizeof strings / sizeof strings[0]) return NULL;
        n = strlen(strings[index]);
        if (n > 32) n = 32;
        for (size_t i = 0; i < n; i++) desc_str[1 + i] = (uint8_t)strings[index][i];
    }
    desc_str[0] = (uint16_t)((TUSB_DESC_STRING << 8) | (2 * n + 2));
    return desc_str;
}
```

TinyUSB는 `tud_descriptor_device_cb()`, `tud_descriptor_configuration_cb()`, `tud_descriptor_string_cb()` 세 callback으로 descriptor를 묻습니다. string descriptor는 UTF-16LE이고 첫 word의 하위 byte가 길이(byte), 상위 byte가 type 0x03입니다. index 0은 지원 언어 목록이라 0x0409(English, United States) 하나를 돌려줍니다.

### 3. `main.c`

```c
/* main.c */
#include "stm32f4xx.h"
#include "tusb.h"
#include "gpio.h"

void clock_init_168mhz(void);           // 4-04: SYSCLK 168 MHz, PLLQ 48 MHz

static volatile uint32_t ms_ticks;
void SysTick_Handler(void) { ms_ticks++; }
uint32_t tusb_time_millis_api(void) { return ms_ticks; }

void OTG_FS_IRQHandler(void) { tusb_int_handler(0, true); }

static void usb_hw_init(void) {
    RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;
    // PA11 = OTG_FS_DM, PA12 = OTG_FS_DP, AF10
    gpio_init(GPIOA, 11, &(gpio_config_t){.mode=GPIO_MODE_AF, .speed=GPIO_SPEED_VH, .af=10});
    gpio_init(GPIOA, 12, &(gpio_config_t){.mode=GPIO_MODE_AF, .speed=GPIO_SPEED_VH, .af=10});
    RCC->AHB2ENR |= RCC_AHB2ENR_OTGFSEN;
}

int main(void) {
    clock_init_168mhz();
    SysTick_Config(168000000u / 1000u);
    usb_hw_init();

    tusb_rhport_init_t dev_init = { .role = TUSB_ROLE_DEVICE, .speed = TUSB_SPEED_AUTO };
    tusb_init(0, &dev_init);

    for (;;) {
        tud_task();                     // handles enumeration and class requests
        if (tud_cdc_available()) {
            uint8_t buf[64];
            uint32_t n = tud_cdc_read(buf, sizeof buf);
            tud_cdc_write(buf, n);      // echo
            tud_cdc_write_flush();
        }
    }
}
```

`clock_init_168mhz()`는 [4-04](/blog/embedded/modern-recipes/part4-04-clock-setup), `gpio_init()`은 [4-03](/blog/embedded/modern-recipes/part4-03-gpio-driver)의 것입니다. `OTG_FS_IRQHandler`의 이름은 CMSIS `startup_stm32f407xx.s`의 vector table 이름과 같아야 합니다. TinyUSB의 STM32F4 board 코드(`hw/bsp/stm32f4/family.c`)도 같은 handler에서 `tusb_int_handler(0, true)`를 부릅니다.

VBUS 핀(PA9)은 쓰지 않았습니다. TinyUSB `dcd_dwc2.c`는 초기화에서 `GOTGCTL`에 BVALOEN·BVALOVAL을 세워 "force B Valid"로 두므로, VBUS를 감지하지 않아도 device로 동작합니다. 대신 케이블을 뽑아도 core가 그것을 VBUS로 알아차리지 못합니다.

### 4. 빌드

TinyUSB 0.18.0, CMSIS(cmsis-device-f4의 `startup_stm32f407xx.s`·`system_stm32f4xx.c`), 그리고 C 라이브러리가 필요합니다. 이 환경의 arm-none-eabi-gcc 16.2.0에는 newlib가 없어 Debian의 `picolibc-arm-none-eabi` 1.8.10-2 패키지에서 header와 `libc.a`(thumb/v7e-m/nofp)를 꺼내 썼습니다. linker script는 [4-01](/blog/embedded/modern-recipes/part4-01-first-baremetal)의 것(FLASH 512 KiB, RAM 128 KiB)입니다.

```bash
git clone --depth 1 --branch 0.18.0 https://github.com/hathach/tinyusb.git
T=tinyusb; CMS=cmsis-device-f4; PL=picolibc/usr/lib/picolibc/arm-none-eabi
CF="-mcpu=cortex-m4 -mthumb -mfloat-abi=soft -O2 -Wall -Wextra \
    -ffunction-sections -fdata-sections -DSTM32F407xx \
    -isystem $PL/include -I src -I $T/src -I CMSIS/Core/Include -I $CMS/Include"
arm-none-eabi-gcc $CF -nostdlib -Wl,--gc-sections -T stm32f411.ld -o cdc.elf \
    $CMS/Source/Templates/gcc/startup_stm32f407xx.s \
    src/main.c src/usb_descriptors.c src/gpio.c src/clock.c \
    $CMS/Source/Templates/system_stm32f4xx.c \
    $T/src/tusb.c $T/src/common/tusb_fifo.c \
    $T/src/device/usbd.c $T/src/device/usbd_control.c \
    $T/src/class/cdc/cdc_device.c \
    $T/src/portable/synopsys/dwc2/dcd_dwc2.c $T/src/portable/synopsys/dwc2/dwc2_common.c \
    $PL/lib/thumb/v7e-m/nofp/libc.a -lgcc
arm-none-eabi-size cdc.elf
```

```text
   text	   data	    bss	    dec	    hex	filename
  12376	     21	    920	  13317	   3405	cdc.elf
```

경고 없이 빌드되고, TinyUSB device stack과 CDC class, DWC2 driver를 합친 이미지가 flash 12.4 KB, RAM(data + bss) 941 byte입니다.

## 측정 / 동작 확인

### host에서 descriptor 풀기

`usb_descriptors.c`를 host(clang)에서 TinyUSB header와 함께 컴파일하고, callback이 돌려주는 byte를 descriptor 길이 단위로 끊어 찍었습니다. host가 enumeration에서 읽는 것과 같은 byte입니다.

```c
/* desc_dump.c */
#include <stdio.h>
#include "tusb.h"

static void dump(const char *name, const uint8_t *p, int n) {
    printf("%s (%d bytes)\n", name, n);
    for (int off = 0; off < n; off += p[off]) {
        printf("  len=%2u type=0x%02X:", p[off], p[off + 1]);
        for (int i = 0; i < p[off]; i++) printf(" %02X", p[off + i]);
        printf("\n");
        if (p[off] == 0) break;
    }
}

int main(void) {
    const uint8_t *dev = tud_descriptor_device_cb();
    dump("device", dev, dev[0]);
    const uint8_t *cfg = tud_descriptor_configuration_cb(0);
    dump("configuration", cfg, cfg[2] | (cfg[3] << 8));
    const uint16_t *s = tud_descriptor_string_cb(2, 0x0409);
    printf("string 2: len=%u type=0x%02X \"", s[0] & 0xFF, s[0] >> 8);
    for (int i = 1; i < (s[0] & 0xFF) / 2; i++) putchar((char)s[i]);
    printf("\"\n");
    return 0;
}
```

```bash
clang -O2 -Wall -I src -I tinyusb/src -o desc_dump desc_dump.c src/usb_descriptors.c && ./desc_dump
```

  len= 9 type=0x04: 09 04 00 00 01 02 02 00 04

  len= 5 type=0x24: 05 24 01 00 01
  len= 4 type=0x24: 04 24 02 06

device descriptor의 `EF 02 01`, configuration의 `4B 00`(75), `80 32`, IAD(type 0x0B), interface의 class `02`·`0A`, endpoint `81 03 08 00 10`(interrupt, 8 byte, interval 16)과 `02 02 40 00`·`82 02 40 00`(bulk, 64 byte)이 핵심 개념의 표와 같습니다.

### 보드에서

보드를 꽂은 뒤 Linux에서 `lsusb`에 `cafe:4001`이 보이고 `dmesg`에 `cdc_acm` 줄이 나오면 enumeration이 끝난 것입니다. `lsusb -v -d cafe:4001`의 출력은 위 dump와 같은 값을 사람이 읽기 좋게 푼 것입니다. 이 글은 보드로 이 단계를 실행하지 않았습니다.

장치가 아예 안 보이면 48 MHz clock(PLLQ)과 PA11/PA12 AF10 설정, `OTG_FS_IRQHandler` 이름을 봅니다. 보이는데 descriptor 오류가 나면 위 dump로 wTotalLength와 실제 길이가 같은지 봅니다.

## 자주 보는 함정

> ⚠️ 48 MHz가 아님

OTG_FS는 PLL의 Q 출력에서 전용 48 MHz를 받습니다. SYSCLK을 바꾸면서 Q를 그대로 두면 48 MHz가 깨집니다. HAL `stm32f4xx_hal_rcc_ex.h`도 "you have to set the PLLQ parameter correctly to have 48 MHz clock for the USB"라고 적습니다.

> ⚠️ wTotalLength와 실제 길이 불일치

configuration descriptor의 wTotalLength는 뒤따르는 interface·endpoint descriptor를 모두 합한 길이입니다. 위 코드는 `TUD_CONFIG_DESC_LEN + TUD_CDC_DESC_LEN`으로 계산해 손으로 75를 쓰지 않습니다.

> ⚠️ 외부 DP pull-up을 또 닮

DS8626의 RPU(PA12)가 이미 1.5 ~ 2.1 kΩ입니다. 외부 pull-up을 더하면 TinyUSB가 SDIS로 연결을 끊어도 DP가 올라가 있어 host가 device를 계속 붙은 것으로 봅니다.

> ⚠️ interrupt handler 이름 오타

`OTG_FS_IRQHandler`가 아니면 vector table의 weak default handler가 남아, USB interrupt가 오는 순간 default handler의 무한 loop로 들어갑니다([4-05](/blog/embedded/modern-recipes/part4-05-interrupt-handling)에서 같은 현상을 QEMU로 보였습니다).

> ⚠️ 시험용 VID를 제품에 씀

0xCAFE는 TinyUSB 예제의 값입니다. 제품은 USB-IF에서 할당받은 VID를 씁니다.

## 정리

- STM32F407 OTG_FS는 **내장 transceiver·내장 DP pull-up·전용 48 MHz**(PLLQ).
- TinyUSB는 **세 descriptor callback + `tud_task()` + `OTG_FS_IRQHandler`**로 붙습니다.
- CDC ACM은 **IAD + 제어 interface(interrupt EP) + data interface(bulk EP 2개)**, wTotalLength 75.
- 빌드 결과는 **flash 12.4 KB, RAM 941 byte**(TinyUSB 0.18.0, -O2).
- descriptor는 **host에서 byte로 풀어** 보드 없이도 확인할 수 있습니다.

다음 편은 **Ethernet MAC + PHY (lwIP)**입니다. RMII, MDIO, lwIP raw API, DHCP를 다룹니다.
