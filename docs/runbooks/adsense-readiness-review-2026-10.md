# AdSense 준비 상태 점검 및 재신청 계획

점검 기준일: 2026-10-10  
점검 대상: 공개 배포된 `https://hawk90.github.io/`(2026-10-10부터 `https://hawk90.dev/`로 이전), Google Search Console, AdSense 사이트 상태  
점검 방법: 세 차례 점검을 합쳤다. 1차는 공개 사이트 구조와 Google 기준 대조, 2차는 sitemap 전수 측정(1,321 URL, 글 726편)과 Search Console·AdSense 화면 확인, 3차는 저장소 원문 기준 글 단위 1차 분류(직접 경험 표현·분량·코드 비중)와 시리즈 간 주제 중복 확인이다. 서로 다른 주장은 공개 사이트나 저장소에서 다시 확인해 아래 "교차 검토" 표에 결과를 남겼다.

## 결론

**지금 바로 재신청하면 통과 가능성은 5% 안팎이다.** 콘텐츠 품질 이전에, Google이 블로그 글을 하나도 보지 못하고 있기 때문이다. 차단은 점검 당일 풀었지만, 색인이 실제로 쌓이기 전까지는 이 판단이 유지된다.

- Search Console에 `https://hawk90.github.io/blog/`로 **시작하는 모든 URL**의 임시 삭제 요청이 걸려 있었다(2026-05-30 요청). 점검 당일 운영자가 취소했다("요청 취소됨").
- 점검 시점에 제출된 sitemap이 없었고, 색인된 페이지는 2개였다(홈, `/revue`). 점검 당일 `sitemap-index.xml`을 제출했고 Google이 아직 읽지 않은 상태다.
- AdSense 사이트 상태는 "주의 필요 / 가치가 별로 없는 콘텐츠"이고 마지막 검토일은 **2026-06-09**다. 삭제 요청 열흘 뒤라, 심사 시점의 사이트는 Google 입장에서 홈 화면뿐이었다.
- 같은 날 사이트를 커스텀 도메인 `hawk90.dev`로 옮겼다. 옛 주소는 경로를 유지한 채 301로 넘어가고, Search Console 주소 변경과 AdSense 사이트 등록(심사 요청 없음)까지 마쳤다. 자세한 기록은 아래 "도메인·메일 전환" 절에 있다.
- 같은 도메인에서 서비스되던 revue·metl 자동 생성 API 문서(약 4,400쪽)는 Pages를 꺼서 내렸고, AdSense 자동 광고는 글 페이지에만 낮은 밀도로 설정했다(아래 "자동 광고 설정").

색인 차단을 풀고 색인이 쌓인 뒤 재신청하면 **30~45%**, 아래의 공개 범위 정리와 핵심 글 강화까지 마치면 **50~65%** 정도로 본다. 모든 수치는 Google 공식 확률이 아니라 측정값과 반려 이력을 바탕으로 한 판단이다.

> 1차 점검은 공개 사이트만 보고 현 상태 통과 가능성을 30~45%로 추정했다. 2차 점검에서 색인 차단이 확인되어 현 상태 추정치를 낮췄고, 30~45%는 "색인 회복 후" 값으로 옮겼다.

## Google 기준

Google은 AdSense 준비 사이트에 다음을 요구한다.

- 방문자에게 유용한 충분한 콘텐츠
- 고유하고 독창적인 내용
- 명확하고 사용하기 쉬운 탐색 구조
- 외부 자료를 참고하더라도 작성자의 전문 지식·분석·개선점이 드러나는 내용
- 광고 크롤러가 접근 가능한 공개 사이트와 정상적인 사용자 경험

### 이번 반려 문구와 세 문서의 직접적인 의미

- thin content는 단순히 글자 수가 적다는 뜻이 아니라, 페이지가 다른 자료와 비교해 실질적인 추가 가치를 거의 제공하지 않는다는 뜻이다.
- Google은 비슷한 페이지가 많으면 각 페이지를 확장하거나 하나로 통합하라고 안내한다.
- doorway·cookie-cutter 페이지와 검색어만 바꾼 반복 페이지는 광고가 게재되는 화면에서도 문제가 될 수 있다.
- 광고 정책상 Search spam 정책을 지켜야 하며, 콘텐츠가 충분히 고유하고 사용자가 다시 방문할 이유가 있어야 한다.
- 따라서 726편 전체를 대상으로 얇음·중복·목록성·템플릿 반복을 검사해야 하며, Modern Embedded Recipes만 점검해서는 부족하다.

첫 번째 문서는 Search Console 수동 조치 도움말이지만, 2026-10-10 기준 Search Console → 직접 조치는 "감지된 문제 없음"이다. 수동 조치가 걸린 것이 아니라 그 기준으로 콘텐츠를 다시 보라는 안내다. 재검토 요청은 Search Console이 아니라 AdSense 사이트 페이지에서 한다.

블로그 글 726편보다 많은 약 4,400개의 자동 생성 페이지가 같은 도메인에 있다. 블로그 sitemap에는 들어 있지 않지만 README·crates.io 링크로 발견될 수 있다. AdSense 문서가 지적하는 "자동화된 기법으로 만든, 추가 가치가 적은 페이지"로 사이트 전체가 평가될 위험이 있다.

**1차 조치 (2026-10-10):** 두 저장소의 Pages 배포본 모든 페이지에 `<meta name="robots" content="noindex, follow">`를 넣었다([hawk90/revue#933](https://github.com/hawk90/revue/pull/933), [hawk90/metl#253](https://github.com/hawk90/metl/pull/253)). 배포 후 대표 경로에 `noindex`가 들어간 것을 확인했다.

**최종 조치 (같은 날): Pages를 끈다.** `noindex`는 검색 색인만 막는다. AdSense는 2023년부터 하위 도메인까지 루트 도메인의 일부로 심사하므로, 같은 도메인에 자동 생성 문서가 열려 있는 것 자체가 위험으로 남는다. 별도 하위 도메인으로 옮겨도 분리되지 않는다. revue는 docs.rs가 정식 문서이고 metl은 저장소 README로 충분해서, 심사가 끝날 때까지 두 저장소의 Pages를 끄기로 했다.

- revue: Pages 배포 워크플로(`cd.yml`)를 지우고 `Cargo.toml`의 `homepage`를 뺐다 — [hawk90/revue#948](https://github.com/hawk90/revue/pull/948)
- metl: `deploy-docs` job과 README 배지를 지우고, CI 게이트 검사가 존재하는 job만 세도록 고쳤다 — [hawk90/metl#278](https://github.com/hawk90/metl/pull/278)
- 두 저장소 모두 Pages 설정을 껐다. `hawk90.dev/revue/`, `hawk90.dev/metl/`은 404다.

이제 GitHub Pages가 켜진 저장소는 블로그뿐이다. 새 저장소에 Pages를 켜면 같은 도메인 아래로 붙으므로, 심사가 끝나기 전에는 켜지 않는다.

### 도메인과 DNS

| 항목 | 설정 | 이유 |
|---|---|---|

GitHub 쪽은 계정 단위 verified domain 등록, 저장소 Pages 커스텀 도메인 `hawk90.dev`, HTTPS 강제를 켰다. GitHub가 Let's Encrypt 인증서(`CN=hawk90.dev`, 2027-01-08 만료)를 자동 갱신한다. 옛 주소 `hawk90.github.io/...`는 같은 경로로 301된다.

**프록시를 켜지 않는 이유.** GitHub Pages 레코드에 Cloudflare 프록시를 켜면 GitHub가 DNS를 확인하지 못하고 Let's Encrypt 갱신 요청(80번 포트)도 프록시가 바꿔 버려, 몇 달 뒤 인증서 갱신이 실패한다. Full (strict)와 겹치면 만료일에 사이트가 열리지 않는다. GitHub Pages는 이미 자체 CDN(Fastly) 뒤에 있어 프록시로 얻는 이점도 작다. 그래서 Cloudflare 대시보드의 "Proxying is required…" 안내는 무시한다. Cloudflare의 캐시·보안 기능이 필요해지면 프록시를 덧대지 말고 호스팅을 Cloudflare Pages로 옮긴다(아래 "호스팅·저장소 용량 계획").

참고: [Let's Encrypt 커뮤니티](https://community.letsencrypt.org/t/fyi-for-github-pages-or-vercel-netlify-with-cloudflare/231054), [GitHub 커뮤니티](https://github.com/orgs/community/discussions/22052)

`hawk90.dev`를 사이트로 추가하고 소유권을 확인했다. 목록·정책 페이지에서 광고 스크립트를 뺐기 때문에 "코드 스니펫" 방식(홈에서 코드를 찾음)은 실패하고, **Ads.txt 방식**으로 확인했다. 심사 요청은 하지 않았다. 재신청은 6단계 품질 게이트를 통과한 뒤에 한다.

## 자동 광고 설정 (2026-10-10)

심사 요청 없이 `hawk90.dev`의 자동 광고를 미리 설정해 두었다. 목표는 승인 뒤에도 글을 읽는 데 방해가 되지 않는 수준이다. AdSense 화면의 "사이트에 적용"은 설정 저장일 뿐 심사 요청이 아니다.

### 광고가 붙는 페이지

광고 스크립트는 글 페이지(`src/pages/blog/[...slug].astro`)에서만 로드된다. 홈, `/blog/`·카테고리·시리즈 목록, 태그, 학습경로, 아카이브, about·contact·privacy·resume는 `noAds`를 넘기고, `/admin`·`/settings`·`/components`·`/404`는 `ADS_CONFIG.excludePaths`로 빠진다. `random`·`series/*`·`topics/*`는 리디렉션 페이지라 레이아웃을 쓰지 않는다. 배포본에서 홈·`/blog/`·카테고리·시리즈 목록·`/blog/2/`·`/tags/`·`/paths/`·`/archive/`는 광고 스크립트 0회, 글 페이지는 1회인 것을 확인했다.

AdSense 페이지 제외는 코드가 놓치는 경우를 위한 보조 장치다. `/blog/`를 섹션으로 제외하면 글까지 빠지므로 "이 페이지만"으로 둔다.

| 방식 | URL |
|---|---|
| 이 페이지만 | `hawk90.dev`, `hawk90.dev/blog/` |
| 섹션 전체 | `/about/`, `/contact/`, `/privacy/`, `/resume/` |

| 기존 광고 최적화 허용 | 끔 | 같은 이유 |
| 앵커 | 켬, 모바일 하단만. 동적 앵커·데스크톱 앵커 끔 | Better Ads 기준에서 작은 하단 고정 광고는 허용된다 |
| 사이드 레일·모바일 전면광고 | 끔 | 전면광고는 페이지를 옮길 때마다 화면 전체를 덮어 읽기 흐름을 끊고, 사이드 레일은 데스크톱 오른쪽 목차와 자리가 겹칠 수 있다 |
| 의도 기반 형식 | 끔 | 본문 단어에 광고 링크를 거는 방식이라 본문과 구분이 흐려진다 |
| 자동 최적화 | 끔(실험 우수 설정 자동 적용도 끔) | 켜 두면 트래픽 50%로 실험해 위 설정보다 광고를 늘릴 수 있다 |

근거 측정(공개 글 표본, headless Chromium): 본문 높이는 모바일(390px) p10 약 7,300px·중앙값 약 9,900px·p90 약 13,700px, 데스크톱(1,440px) 중앙값 약 7,500px이다. 간격 1,000px이면 중앙값 글은 모바일·데스크톱 모두 상한 6개에 걸린다(실제 글 미리보기도 6개). 광고 하나를 약 280px로 잡으면 본문 높이 대비 광고 높이는 모바일 약 17%로, Better Ads의 모바일 광고 밀도 상한 30%보다 낮다. 데스크톱은 밀도 상한이 없고 팝업·대형 고정 광고 등 형식 기준만 있는데, 해당 형식은 모두 껐다. 헤더(65px)는 sticky이고, 모바일 목차와 데스크톱 사이드바 목차가 있다.

### 제외 영역

AdSense 정책은 내비게이션 바로 옆처럼 실수로 누르기 쉬운 자리의 광고를 금지한다. 실제 글(`part12-07-thermal`)로 미리보기를 열어 후보 자리를 보고 다음 3곳을 뺐다.

1. 사이트 헤더 바로 아래(경로 표시 위)
2. 시리즈 표시와 글 제목 사이
3. 모바일 목차 버튼 바로 아래

저자 소개, 이전/다음 글, 시리즈 목록 근처에는 후보 자리가 없었다. 남는 자리는 본문 섹션 사이와 본문 끝이다. 제외 영역은 Google이 "레이아웃이 비슷한 페이지"에 적용하는 방식이라 모든 글에 같게 걸린다는 보장은 없다. 승인 뒤 시리즈별로 글을 몇 개 열어 상단에 광고가 붙지 않는지 확인한다.

## 호스팅·저장소 용량 계획

DB가 없는 정적 사이트라 유지비는 도메인 값(연 약 \$12)뿐이다. 트래픽보다 먼저 부딪히는 한계는 용량이다.

| 대상 | 현재 (2026-10-10) | 한도 | 넘으면 |
|---|---|---|---|
| 빌드 결과물 `dist` | 약 400MB, 파일 4,348개. 글 HTML이 편당 약 260~320KB(대부분 반복되는 시리즈 목차), OG 이미지 91MB | GitHub Pages 1GB | 호스팅을 Cloudflare Pages로 옮긴다(무료, 대역폭 무제한, 파일 20,000개 제한). 도메인이 Cloudflare에 있으므로 DNS만 바꾸면 된다 |
| 저장소 `.git` | 압축 약 70MB. 이력 기준 `public/images`(생성 SVG) 24.7MB, `src/content` 15.8MB, `reports/content-export` 15.2MB(버전 2개) | 권장 1GB, 파일당 100MB | 저장소는 옮기지 않는다. 생성물을 커밋에서 빼고, 큰 이미지는 Cloudflare R2로 분리한다 |
