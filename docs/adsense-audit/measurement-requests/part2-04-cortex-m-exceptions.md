## 1. Exception entry, return+re-entry, and tail-chain cycle counts on a real STM32F407, both inside the TRM 3.9.1 zero-wait condition and outside it. This fills the gap the post states at L71, where no cycle figure exists for FLASH_ACR LATENCY > 0.

- **준비:** STM32F407 board (e.g. STM32F4DISCOVERY or NUCLEO-F407ZG; record the exact board and silicon revision from DBGMCU->IDCODE REV_ID). Toolchain arm-none-eabi-gcc (record the version and -O level), CMSIS 5.9.0 core_cm4.h, cmsis_device_f4 v2.6.9, HAL v1.8.5 if used, and an ST-LINK with OpenOCD or STM32CubeProgrammer. Optional: a logic analyzer (e.g. Saleae; record the sample rate) on two GPIO pins. Use four clock and flash configurations: (a) HSI 16 MHz, LATENCY=0. (b) 168 MHz, LATENCY=5, ART on (FLASH_ACR ICEN=1, DCEN=1, PRFTEN=1). (c) 168 MHz, LATENCY=5, ART off. (d) 168 MHz with the vector table and handlers copied to SRAM (VTOR in SRAM). Record each FLASH_ACR value read back from the chip.
- **절차:** 1. Enable DWT: CoreDebug->DEMCR |= TRCENA, DWT->CYCCNT = 0, DWT->CTRL |= CYCCNTENA. 2. Baseline: time two back-to-back CYCCNT reads to get the measurement overhead. 3. Entry: t0 = DWT->CYCCNT, then NVIC->STIR = EXTI0_IRQn (a software trigger). The handler reads CYCCNT as its first C statement; check this in the disassembly with objdump -d and record how many instructions come before the read. Store t1. Repeat 1000 times and record min, max and median of t1 - t0 - overhead. 4. Return + re-entry: pend USART1 from the end of the EXTI0 handler after it exits (e.g. from thread code immediately after return), and record the gap between the EXTI0 last instruction and the USART1 first instruction. 5. Tail-chain: with EXTI0 (prio 2) running, pend USART1 (prio 7) via STIR inside the EXTI0 handler. Record CYCCNT at the EXTI0 handler's last statement and at the USART1 handler's first statement. 6. As a cross-check, toggle a GPIO via BSRR at the handler boundaries and capture with the logic analyzer. 7. Repeat steps 3-5 for configurations (a)-(d).
- **기록할 것:** A table with one row per configuration (a)-(d). Columns: SYSCLK, FLASH_ACR read-back hex, entry cycles (min/median/max), return-to-re-entry cycles, tail-chain cycles, and measurement overhead subtracted. Also record the compiler version and flags, the objdump excerpt showing the handler prologue before the CYCCNT read, the IDCODE, and the date. Keep raw CSV or a log. Note any outliers and the limits: STIR store latency is included, and CYCCNT is read after the prologue, not at the first instruction.
- **글에 넣을 위치:** Section '3) Tail-chaining과 late-arrival', right after L69-71: a measured table next to the TRM figures, labeled as measured on the named board and config. Then L104 can point to this table instead of saying cycle counts are omitted, and L170's summary bullet can state the measured difference.
- **오르는 항목:** C: real measurement with environment and an environment difference (zero-wait vs LATENCY=5, ART on/off, SRAM vectors) moves C from ≤9 into 12-15. A: replaces the 'no number exists' gap with the author's own data and a selection criterion (e.g. put vectors and ISRs in SRAM when latency matters), which adds value beyond the TRM.

## 2. Observed execution order and stack behavior for each row of the scenario table (L106-113). These rows are currently derived from UG rules only.

- **준비:** The same STM32F407 board and toolchain as item 1. Priorities exactly as in the post: EXTI0=2, USART1=7, SysTick=15, with HAL_Init (PRIGROUP 3) or reset AIRCR. Record the AIRCR read-back. A RAM trace buffer of struct {uint32_t cyccnt; uint32_t ipsr; uint32_t msp;}.
- **절차:** 1. In each handler, log CYCCNT, __get_IPSR() and __get_MSP() at entry and exit into the trace buffer. 2. Row 1 (preemption): inside the USART1 handler, trigger EXTI0 via NVIC->STIR (or the EXTI SWIER register). 3. Row 2 and row 5 (tail-chain, same group): pend USART1 inside EXTI0. Then set EXTI0 priority to 7 and repeat. 4. Row 4: let SysTick fire while USART1 busy-loops. 5. Row 6: __set_BASEPRI(0x30), pend both IRQs, log, then __set_BASEPRI(0). 6. Late-arrival row 3: try to hit the stacking window, e.g. a timer compare event that drives EXTI0 a few cycles after a USART1 STIR write; sweep the delay. Record whether a late-arrival was actually observed. If it was not, say so and do not claim it. 7. Dump the trace buffer over the debugger (OpenOCD 'mdw') or over UART after the test.
- **기록할 것:** For each row: the raw trace lines (IPSR sequence, MSP values, CYCCNT deltas). Preemption should show MSP lower by the frame size (32 bytes, or more with FP context). Tail-chain should show the next handler starting with the same MSP and no thread-mode gap. Record the AIRCR value, the BASEPRI read-back (expect 0x30), and for late-arrival the delay sweep and the outcome (observed or not observed).
- **글에 넣을 위치:** Section '이 설정에서 예외 경로': add a column or a short block under the table at L106-113 with the observed IPSR order and MSP delta per row, labeled with the board and date. Put the late-arrival attempt result as a note under row 3.
- **오르는 항목:** C: turns a rule-derived table into observed results (a reproducible procedure plus an observation) and lifts C into 8-11. Together with item 1 it can reach 12+. A: the MSP-delta evidence that tail-chaining skips unstacking is the author's own demonstration rather than a restatement of the UG.

## 4. Bootloader→application handoff failure reproduction: the pending SysTick/PendSV that survives SysTick->CTRL=0 (issue B at L119-143), and the SystemInit VTOR pitfall (L148).

- **준비:** STM32F407 with a two-image layout: bootloader at 0x08000000, application at 0x08010000, as in the post. Same toolchain. A debugger for reading SCB->ICSR, VTOR, SHCSR and CONTROL. The application logs its first handler entries into a RAM buffer, or toggles a GPIO.
- **절차:** 1. In the bootloader, run SysTick at 1 ms and call the post's jump_to_app() unchanged. Before the jump, read SCB->ICSR (PENDSTSET bit 26, PENDSVSET bit 28), SHCSR, CONTROL and BASEPRI. 2. In the application, before it configures SysTick, log whether SysTick_Handler runs right after __enable_irq(). Repeat about 100 times, or force the case by setting PENDSTSET just before the jump. 3. Add SCB->ICSR = SCB_ICSR_PENDSTCLR_Msk | SCB_ICSR_PENDSVCLR_Msk before VTOR and repeat. 4. VTOR pitfall: build the application with USER_VECT_TAB_ADDRESS defined and VECT_TAB_OFFSET left at 0. Read SCB->VTOR after SystemInit and record what happens on the first IRQ (which handler runs, HardFault or not; record the CFSR/HFSR values if it faults). 5. Build with both settings correct and confirm that VTOR reads 0x08010000.
- **기록할 것:** ICSR/SHCSR/CONTROL/BASEPRI hex before the jump. The count of spurious early SysTick_Handler entries with and without the ICSR clear (N out of 100). The VTOR read-back for each SystemInit setting, and the observed outcome of the first IRQ, with fault register values if any. Board, tool versions, date.
- **글에 넣을 위치:** 'Bootloader에서 application으로 넘기기': add the ICSR line to the code at L119-138 with the observed before/after counts in the bullet list at L143-146. Add the VTOR read-back and the observed failure to the paragraph at L148.
- **오르는 항목:** C: 실패·환경 차이 recorded with commands and results moves C into the 12-15 band. A: a first-hand failure case and its fix make the handoff recipe distinct from vendor app notes. Also resolves the B issue with evidence rather than inference.

## 5. Effect of PRIGROUP 7 (HAL NVIC_PRIORITYGROUP_0) versus PRIGROUP 3 on EXTI0 latency while a long low-priority handler runs (pitfall at L163-165).

- **준비:** STM32F407, a logic analyzer on the EXTI0 input pin (driven by a function generator or a second GPIO) and on a GPIO toggled at EXTI0 handler entry. USART1 handler is artificially long (e.g. a busy loop of a fixed CYCCNT length, recorded).
- **절차:** 1. With PRIGROUP 3 and priorities 2/7, assert the EXTI0 pin while the USART1 handler runs, and capture pin→handler-GPIO latency over about 100 events. 2. Switch to HAL_NVIC_SetPriorityGrouping(NVIC_PRIORITYGROUP_0) and repeat. 3. Read AIRCR back in both cases.
- **기록할 것:** AIRCR hex for each case. Latency distribution (min/median/max in µs and cycles at the recorded SYSCLK) for both groupings. The long-handler length. Logic-analyzer screenshots.
- **글에 넣을 위치:** '자주 보는 함정 — subpriority만 쓰는 grouping' (L163-165): the measured latency comparison as evidence.
