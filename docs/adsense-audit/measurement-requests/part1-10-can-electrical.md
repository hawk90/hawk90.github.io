> - 목적: 루브릭 C(실전성)·A(독창성)는 작성자가 실제 하드웨어에서 잰 값과 기록이 있어야 오른다. 아래 항목을 측정해 주면 글에 넣는다. 측정하지 않은 항목은 비워 둔다.

## 1. 1. 종단 저항 실측: 전원 OFF / ON, 정상·종단 하나 제거·종단 셋 구성 (C 상한을 묶는 '측정 없음'을 직접 푸는 항목)

- **준비:** 작성자의 실제 CAN 버스. 노드 2개 이상, 노드마다 TCAN1042-Q1(칩 마킹과 변형(-Q1, V 여부)을 기록). 양 끝 120 Ω 종단(저항 값·허용오차·부품번호 기록). 케이블 종류와 길이도 기록. DMM 모델과 저항 측정 범위를 기록.
- **절차:** (a) 모든 노드 전원 OFF, 커넥터에서 CANH–CANL 저항을 잰다. (b) 종단 하나를 뺀 뒤 다시 잰다. (c) 중간 노드에 120 Ω 하나를 더 달고 다시 잰다. (d) 정상 구성으로 되돌려 모든 노드 전원 ON(송신 없음) 상태에서 다시 잰다. 이때 DMM 측정 전류가 버스 bias에 영향을 주므로 값이 흔들리면 흔들린 범위를 그대로 기록한다. 각 구성에서 3회 측정한다.
- **기록할 것:** 구성별 측정값 3회(Ω, 소수 첫째 자리), DMM 모델, 노드 수, 전원 ON 상태의 노드 수. 전원 ON 값이 본문 계산(30 노드 최악 56.6 Ω)과 어떻게 다른지는 실제 노드 수로 다시 계산해 비교한다(예: 2노드면 RID 30~80 kΩ 두 개가 병렬). 측정하지 않은 구성은 칸을 비운다.
- **글에 넣을 위치:** L61-67 표에 '측정값(작성자 보드)' 열 추가, 또는 「보드에서 확인하는 순서」 1단계 아래에 측정 환경 한 줄 + 결과 표. 같은 내용을 두 곳에 반복하지 말 것(padding 지적 L234-236).
- **오르는 항목:** C (재현 절차 → 실측 결과 기록, 8~11 → 12 쪽으로). 종단 누락·과다 구성은 '실패' 사례로 A의 실패 사례 요건에도 기여.

## 2. 2. Recessive/dominant 레벨 스코프 캡처: CANH, CANL, math(CH1−CH2), 정상 60 Ω과 종단 오류 구성 비교

- **준비:** 1번과 같은 버스. 스코프 모델·대역폭·프로브(감쇠비, 수동/차동), 두 채널 모두 같은 노드 GND에 접지. 송신 노드 MCU와 bitrate(가능하면 1 Mbit/s와 500 kbit/s 둘 다), 송신 frame ID·DLC. transceiver VCC 실측값도 함께 기록(recessive typ 0.5×VCC 비교용).
- **절차:** (a) 송신 없음: CANH, CANL DC 레벨과 math 평균을 잰다(스코프 measure의 mean). (b) 주기적 frame 송신: dominant 구간에서 CANH, CANL, math의 mean(또는 커서) 값을 잰다. (c) 종단 하나 제거(120 Ω 부하), 종단 셋(40 Ω 부하)에서 (b)를 반복하고 에지 부근 링잉/계단 파형을 같은 timebase로 캡처한다. (d) 각 캡처는 원본 스크린샷 파일로 남긴다.
- **기록할 것:** 구성별 recessive VOD(mV), dominant CANH/CANL/VOD(V), VCC(V), 측정 온도(대략 실온이면 실온 °C). 캡처 PNG 원본(축 눈금·timebase·channel 설정이 보이도록). 40 Ω·120 Ω 구성의 VOD가 데이터시트 VOD 조건 밖이라는 점은 본문 문장 그대로 두고, 측정값은 '이 보드 한 대의 값'으로 표시.
- **글에 넣을 위치:** 「보드에서 확인하는 순서」 2·3단계에 측정값 표 1개 + 캡처 1~2장(정상, 종단 누락). 캡처는 public/images/blog/... 아래 이미지 파일과 alt 텍스트가 필요하므로 이미지 추가는 작성자 결정. 1) 차동 신호 절 L49-53의 '읽는 방법'에서 해당 캡처를 한 번 가리키기.
- **오르는 항목:** C (실제 파형·환경 차이 기록 → 12 이상 근거). A (데이터시트 표를 작성자 보드 값과 대조한 결과는 다른 글에 없는 내용).

## 3. 3. Transceiver loop delay 실측: TXD→RXD, 두 에지 방향(LOOP1/LOOP2)

- **준비:** 노드 하나의 TCAN1042-Q1. TXD·RXD 핀에 프로브(짧은 ground spring), 버스는 정상 60 Ω 종단. 데이터시트 조건(RL 60 Ω, CL 100 pF)과 실제 부하가 다르면 그 차이를 기록. VCC·VIO 실측값, 실온 온도.
- **절차:** (a) 송신 중 TXD 하강 에지(recessive→dominant)와 RXD 하강 에지 사이 시간을 50% 레벨 기준으로 잰다 = LOOP1. (b) TXD 상승 → RXD 상승 = LOOP2. (c) 스코프 통계 기능으로 각 100 에지 이상 수집해 min/mean/max를 기록. (d) 가능하면 노드 2~3개(다른 칩 개체)에서 반복.
- **기록할 것:** 칩 개체별 LOOP1, LOOP2 min/mean/max(ns), 수집 에지 수, 측정 조건(VCC, 부하, 온도). 데이터시트 typ 100/110 ns, max 160/175 ns와 나란히 놓되, 측정값을 길이 예산에 쓰지 않는다는 본문 L238 원칙은 유지.
- **글에 넣을 위치:** 「보드에서 확인하는 순서」 5단계 결과, 그리고 L93-97 고정 지연 표 아래 한 문장("작성자 보드의 칩 N개에서 LOOP1은 ... ns였다; 예산에는 max를 쓴다"). 이 값은 '40 m가 typ로는 통과'라는 L196 판단의 현실성을 독자가 판단하게 해 준다.
- **오르는 항목:** C (환경 차이 기록). A (typ/max 어느 쪽이 실제 부품에 가까운지 1차 데이터로 보여 주는 이 글만의 결과).

## 4. 4. 작성자 케이블의 전파 지연(ns/m) 실측

- **준비:** 본문에서 실제로 쓰는 twisted-pair 케이블(제품명, 규격, 특성 임피던스 표기). 길이가 다른 두 토막(예: 작성자가 가진 길이 L1, L2; 줄자로 잰 실제 길이 기록). 노드 A·B 두 개.
- **절차:** (a) 노드 A가 frame 송신. 노드 A의 TXD와 노드 B의 RXD를 같은 스코프에 건다(두 노드 GND를 공통으로 연결하고 프로브 ground도 공통 GND). (b) A.TXD 하강 → B.RXD 하강 시간을 100 에지 이상 평균. (c) 케이블을 L2로 바꿔 반복. (d) (t2 − t1) / (L2 − L1)로 ns/m를 구한다(transceiver 지연이 상쇄됨).
- **기록할 것:** L1, L2(m), 각 평균 지연(ns)과 표준편차, 계산한 ns/m. 케이블 제품 데이터시트가 velocity factor를 적었다면 그 값과 출처를 함께.
- **글에 넣을 위치:** L87 '케이블: SLLA270 typical 5 ns/m' 뒤에 한 문장으로 작성자 케이블 실측값을 덧붙이고, 차이가 크면 L167-178 길이 계산이 몇 m 움직이는지 한 줄. 표 전체를 다시 쓰지 않는다(variant 축 추가 금지 — 기존 A/F 지적과 충돌).
- **오르는 항목:** C (가정값 하나를 실측으로 대체). A (계산 예산의 입력 하나를 독자 환경에서 재는 방법과 결과).

## 5. 5. 1 Mbit/s · BTR 0x011A0002 (3×14 · 9+2+2)로 실제 길이별 arbitration/에러 시험

- **준비:** STM32F4(본문과 같은 42 MHz APB1 bxCAN; 실제 MCU 품번·HSE 주파수·클록 트리 설정 기록) 노드 2개 이상 + TCAN1042-Q1. 본문 코드의 BTR 값 그대로. 케이블 길이는 작성자가 가진 범위에서 여러 개(예: 짧은 길이, 14 m 근처, 21 m 근처, 가능하면 40 m). 스코프 또는 logic analyzer.
- **절차:** (a) 두 노드가 같은 시점에 송신하도록(외부 GPIO 트리거 또는 같은 주기 타이머) ID가 늦은 비트에서만 다른 frame을 반복 송신해 arbitration을 강제한다. (b) 각 길이에서 N분(예: 10분) 동안 CAN_ESR의 TEC/REC/LEC와 수신 frame 수, 손실 수를 기록한다. (c) 가장 긴 길이에서 A.TXD SOF 에지와 B의 dominant가 A.RXD에 돌아오는 에지를 같은 화면에 캡처해 실제 왕복 시간을 잰다. (d) 같은 길이에서 SJW를 1로 바꾼 설정(본문 L248 Linux 기본값 경우)도 한 번.
- **기록할 것:** 길이별 표: 케이블 길이, 측정 왕복(ns), PROP_SEG 643 ns 대비 여유, 시험 시간, 송신 frame 수, 에러 카운트/LEC 값, bus-off 여부. 왕복 캡처 원본. 에러가 0이어도 '이 보드·실온·이 클록 편차에서 0'이지 보장이 아님을 적는다(Hartwich 2절: Prop_Seg 부족은 '가끔' 에러를 낸다).
- **글에 넣을 위치:** 「40 m 판정」 절 끝 또는 「실제 사용 예」 BTR 값 뒤에 '작성자 보드에서 확인한 결과' 소절 하나. 판정 문장 자체는 반복하지 말고 측정 표만 둔다(B/F padding 지적: 40 m 판정은 한 곳에만).
- **오르는 항목:** C (실제 측정·트레이드오프·환경 차이 → 12~15). A (계산 예산과 실측 왕복을 같은 보드에서 대조한 결과는 이 글만의 핵심 근거, 20점대 근거).

## 6. 6. 각 노드의 실제 CAN 클록 편차 측정 (df 허용치와 비교)

- **준비:** 5번의 노드들. 클록 소스(HSE 크리스털/오실레이터 품번과 표기 허용오차 ppm) 기록. 주파수 카운터 또는 정확도가 명시된 스코프 주파수 측정(장비 모델·timebase 정확도 기록).
- **절차:** (a) 각 노드에서 MCO 핀으로 HSE(또는 SYSCLK 분주)를 출력해 주파수를 잰다. (b) 또는 1 Mbit/s 송신 중 TXD의 비트 폭(SOF 이후 단일 비트들의 평균)을 재서 nominal 1000 ns 대비 편차를 구한다. (c) 실온과, 가능하면 다른 온도(보드 가열/냉각을 할 수 있을 때만) 한 번.
- **기록할 것:** 노드별 측정 주파수(Hz), nominal 대비 편차(ppm, %), 측정 장비 정확도. 본문 표 df ±0.556%, ±0.278%와 비교만 하고 결론을 과장하지 않는다.
- **글에 넣을 위치:** L184-188 경계선 목록 바로 아래 한 문장 ('작성자 보드 노드들의 편차는 측정상 ±x ppm으로 표의 df보다 n배 작다'). 이것으로 독자가 PROP_SEG 쪽으로 TQ를 더 줄지 판단할 수 있다.
- **오르는 항목:** C (트레이드오프의 실제 입력값 기록). A (선택 기준을 실제 수치로 닫음).

## 7. 7. 두 노드 GND 전위차 실측 (분리 전원 / 공통 GND 비교)

- **준비:** 서로 다른 전원(예: 별도 어댑터나 차량/장비 전원)으로 동작하는 노드 2개. 노드 사이 GND 배선 유무, 배선 길이, 부하 전류(다른 부하가 같은 GND를 쓰는지) 기록. transceiver 모드(Normal/Standby).
- **절차:** (a) 본문 4단계대로 노드 A GND 기준 CANH·CANL recessive 전압, 노드 B GND 기준 같은 값을 잰다(배터리 구동 DMM 또는 절연된 스코프 채널; 접지된 스코프 두 대로 서로 다른 GND에 물리지 말 것). (b) 차이로 GND 전위차를 구하고, 두 GND 사이를 DMM DC로 직접 잰 값과 비교한다. (c) GND 선을 연결한 경우/안 한 경우를 각각.
- **기록할 것:** 구성별 각 노드 기준 CANH, CANL(V), 계산한 전위차, 직접 측정 전위차(V), 통신 에러 유무. 측정 장비의 절연 방식.
- **글에 넣을 위치:** 「보드에서 확인하는 순서」 4단계 결과로 한 표. 4) Common-mode 절 L138-140에서 한 번 가리키기.
- **오르는 항목:** C (환경 차이 기록, 4단계 절차의 결과 제시).

## 8. 8. (선택) Linux SocketCAN의 1 Mbit/s 자동 계산 결과 기록

- **준비:** 작성자가 가진 Linux 호스트 + SocketCAN 어댑터(어댑터 모델, 드라이버 이름, 커널 버전 `uname -r`). bxCAN이 아닌 어댑터라면 그 컨트롤러 클록이 다름을 명시.
- **절차:** `sudo ip link set can0 type can bitrate 1000000` → `ip -details link show can0` 출력 전체 저장. 이어서 `sample-point 0.857`을 지정해 다시 설정하고 출력 저장. 가능하면 `tq`, `prop-seg`, `phase-seg1`, `phase-seg2`, `sjw` 명시 설정도 한 번.
- **기록할 것:** `ip -details` 출력 원문(sample-point, tq, prop-seg, phase-seg1/2, sjw, clock 값). 결과를 편집하지 않고 붙인다.
- **글에 넣을 위치:** L107 Linux 기본 sample point 문장과 L206 `prop_seg = tseg1 / 2` 문장 근처에 출력 블록 하나(```text 코드 블록은 실제 명령 출력이므로 규칙에 맞음). L248 SJW 기본값 함정의 실제 확인 예로도 사용.
- **오르는 항목:** C (명령·환경·결과가 함께 있는 재현 기록). part5-10의 'CiA 87.5%' 불일치 해소에도 1차 근거로 쓸 수 있음(D 보조).
