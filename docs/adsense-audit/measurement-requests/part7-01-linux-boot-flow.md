## 1. Capture a baseline: one complete, unedited UART log of a normal boot from power-on to the login prompt, with timestamps on every line. This lets the source-derived strings in the diagnosis table (L86-98) be marked as observed.

- **준비:** NXP i.MX8M Mini EVK, the actual board revision as printed on the silkscreen (record it). flash.bin built locally from U-Boot v2025.04 imx8mm_evk_defconfig plus upstream TF-A v2.12.0 PLAT=imx8mm bl31.bin plus the NXP DDR firmware version actually used (record the firmware-imx package version). Linux v6.12 arm64 defconfig Image, imx8mm-evk.dtb, and an ext4 rootfs on mmcblk1p2 (say what built it, for example Buildroot and its version). Host: USB-UART on the debug micro-USB (UART2 = ttymxc1), 115200 8N1, grabserial (or `picocom --logfile` plus `ts '%.s'`).
- **절차:** 1) `sudo dd if=flash.bin of=/dev/sdX bs=1k seek=33 conv=fsync` as in imx8mm_evk.rst. 2) `grabserial -d /dev/ttyUSB1 -b 115200 -t -m 'U-Boot SPL' -o boot-normal.log`. 3) Power-cycle with the boot switch on SD. Let autoboot run with no keypress. 4) After login, run `cat /proc/cmdline`, `dmesg | grep -iE 'Machine model|EL[12]|earlycon|VFS|Run /'` and `uname -a`, and append the output to the log.
- **기록할 것:** The raw log file, saved unchanged. From it: the exact SPL banner line; whether any PMIC or DDR lines appear; the two 'NOTICE:  BL31:' lines exactly as printed; the U-Boot proper banner; whether 'bootflow scan -lb' booted the board or it fell through to bsp_bootcmd (the lines that show it); the 'Loading Device Tree to …, end … ... OK' addresses; 'Starting kernel ...'; the first kernel line; the VFS mount line; the 'Run /sbin/init as init process' line, as printed. Also record the grabserial timestamp at each of those lines, which gives per-stage elapsed time.
- **글에 넣을 위치:** A new subsection '실제 부팅 로그' between ## 단계별 인계 (ends at L40) and ## U-Boot가 커널에 넘기는 것 (L42). Put a trimmed excerpt (stage-boundary lines only, marked '(중략)') in a ```text block, followed by a small table of stage → first line → timestamp. Then each row of the diagnosis table in ## 콘솔의 마지막 줄로 멈춘 단계 짚기 (L86-98) can say '관찰됨' next to strings that appeared in this log.
- **오르는 항목:** C (moves from source-derived only to a reproducible procedure with an observed result, and above once combined with item 2) and A (the per-stage timing and the actual bootflow-vs-bsp_bootcmd outcome are first-hand results no upstream doc gives).

## 2. Run fault-injection boots. Deliberately break one link at a time, capture the console's actual last lines, and compare them with the diagnosis table. This checks the post's core claim (the last console line tells you the stage) on hardware.

- **준비:** Same board and images as item 1. A spare SD card, so the known-good card stays untouched. One grabserial log per case.
- **절차:** Do each case from a clean power-cycle and keep its log. (a) No SPL: zero the SPL area, `dd if=/dev/zero of=/dev/sdX bs=1k seek=33 count=64`. The post's table (L88) predicts no output. (b) No u-boot.itb: write a flash.bin truncated after SPL, or zero the region where the FIT starts (find the offset in the imx-mkimage/binman output). The post's table (L91) predicts 'SPL: failed to boot from all boot devices' and '### ERROR ###'; record whatever actually prints. (c) Missing DTB: in U-Boot, stop autoboot, disable bootflow with `setenv bootcmd run bsp_bootcmd`, then `setenv fdtfile nonexist.dtb; run bsp_bootcmd`. Record what prints. (d) Wrong partition with rootwait: `setenv mmcroot /dev/mmcblk1p9 rootwait rw; run bsp_bootcmd`. (e) Wrong partition without rootwait: `setenv mmcroot /dev/mmcblk1p9 rw`. (f) Filesystem driver not built in: reformat p2 as a filesystem that is `=m` or unset in the built .config (check `grep CONFIG_<FS>_FS .config` first and record the value), or build a kernel with `CONFIG_EXT4_FS=m`. (g) Foreign-arch /init: build a cpio whose /init is an x86_64 static binary, and pass it as initrd (`booti ${loadaddr} ${initrd_addr}:${filesize} ${fdt_addr_r}`). (h) The same with an armhf (ARM EABI, 32-bit) static /init, which tests the CONFIG_COMPAT / 32-bit EL0 statement at L100 on Cortex-A53.
- **기록할 것:** For each case: the exact command or modification, the last 5-15 console lines copied unedited, and the elapsed time before the hang or panic. For (d)/(e)/(f), note which root-mount messages actually appeared ('Waiting for root device …', a 'VFS: …' line with or without a partition list, or another line), which settles the wording of the L96 row by observation. For (g), whether 'Failed to execute /init (error -8)' appeared and what followed it. For (h), whether the armhf /init ran or failed. Any case where the observed line differs from the table must be reported as it is, not corrected to match.
- **글에 넣을 위치:** ## 콘솔의 마지막 줄로 멈춘 단계 짚기: add a fourth column '이 보드에서 관찰' to the diagnosis table (L86-98) with a short marker, or keep the table and add a subsection '직접 깨뜨려 본 결과' after the L102 paragraph (before ## 정리 at L104). That subsection holds one compact ```text excerpt per case (d, e/f, g) and a sentence on any mismatch. Case (h) goes into the L100 paragraph as an observed confirmation or contradiction of the compat statement.
- **오르는 항목:** C (a reproducible failure procedure with recorded results and environment differences reaches the 12-15 band) and A (real failure cases and a hardware-checked selection criterion for initramfs vs root direct). It also lets the L96 row be split on evidence.

## 3. Verify the handoff on hardware: the exception level the kernel actually started at, and the DTB address the kernel actually received, compared with U-Boot's 'Loading Device Tree to' line. This settles the x0/EL statement that conflicts with sibling chapter19 by measurement.

- **준비:** Same board and images. Kernel command line extended with `memblock=debug`.
- **절차:** 1) Stop autoboot. `setenv mmcargs 'setenv bootargs ${jh_clk} ${mcore_clk} console=${console} root=${mmcroot} memblock=debug'; run bsp_bootcmd`. 2) Capture the U-Boot 'Loading Device Tree to A, end B' line. 3) After boot: `dmesg | grep -E 'started at EL|early_init_fdt_reserve_self|memblock_reserve'`. 4) Optionally, in U-Boot before booting, `fdt addr ${fdt_addr_r}; fdt print /chosen` after `fdt boardsetup`, or after booting `cat /proc/device-tree/chosen/bootargs`, to confirm bootargs was written into /chosen.
- **기록할 것:** The U-Boot DTB copy address range; the kernel's memblock_reserve range attributed to early_init_fdt_reserve_self, and whether it equals A..B; the exact 'CPU: All CPU(s) started at EL…' line as printed; the /proc/device-tree/chosen/bootargs content. Report a mismatch with the post if one occurs.
- **글에 넣을 위치:** ## U-Boot가 커널에 넘기는 것, step 4 of the U-Boot list (L61): one sentence plus a 3-4 line ```text excerpt showing the two addresses and the EL line. Also the 정리 bullet at L107 (DTB address from the 'Loading Device Tree to' line). The same capture can be cited as evidence when chapter19 (bootloader series) is fixed.
- **오르는 항목:** C (turns the central handoff claim, x0 = DTB copy and the EL, into an observed, checkable result) and A (first-hand hardware evidence on the EL the kernel starts at, which is distinctive author value).

## 4. Measure the time cost of the choices the post discusses (earlycon on/off, initramfs vs root direct), so the 정리 criteria carry real numbers instead of only conditions.

- **준비:** Same board. Two kernel/boot variants: (A) root direct as baseline; (B) the same Image plus a minimal busybox initramfs whose /init mounts /dev/mmcblk1p2 and runs switch_root. Record the cpio size. grabserial with -t, or `initcall_debug printk.time=1` on the kernel side.
- **절차:** Boot each variant 5 times from power-on. Measure: 'Starting kernel ...' → first kernel console line (with and without `earlycon`); 'Starting kernel ...' → the 'Run /sbin/init' or '/init' line; for B, also the initrd load time in U-Boot (fatload byte count and time). Use the same SD card and the same power-on method.
- **기록할 것:** A table of median and min/max of the 5 runs per variant, in ms, with the cpio and Image sizes and the SD card model. Do not round, and do not report a single run.
- **글에 넣을 위치:** A short subsection at the end of ## root를 누가 mount하나 (after L80, before L82), or a 2-3 row table in ## 정리 (L104-108) supporting the initramfs decision bullet (L106). The earlycon timing belongs next to the 'Starting kernel ...' row (L94).
- **오르는 항목:** C (a quantified trade-off with environment detail, the 12-15 band) and A (an author-measured selection criterion, the initramfs cost on this board, that other sources do not provide).
