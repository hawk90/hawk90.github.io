## 1. Logic-analyzer capture of the JEDEC ID transaction (9Fh) at BR=010 (10.5 MHz), plus the ID bytes actually read. This turns the 'expected value' table into an observed result.

W25Q32JV part with full marking (IQ/JQ vs IM/JM, date code) and how it is wired (module vs direct, wire or trace length in cm, any series resistors, /CS pull-up value). VDD measured with a multimeter. Logic analyzer model and sample rate, at least 4x SCK (≥ 50 MS/s for 10.5 MHz), with the SPI decoder set to Mode 0, MSB first, 8-bit. Toolchain and CMSIS version used to build the post's code as written.
- **절차:** 1) Build the post's spi1_init/w25q_read_id code unchanged, with the RCC setup the author actually uses. Read RCC->CFGR PPRE2 and SystemCoreClock (or measure SCK on the analyzer) so PCLK2 = 84 MHz is confirmed rather than assumed. 2) Trigger on the /CS falling edge on PA4. 3) Capture /CS, SCK, MOSI and MISO for the whole transaction. 4) Zoom in on one MISO bit transition and note which SCK edge it follows. 5) Print id[0..2] over UART/SWO/debugger.
- **기록할 것:** A screenshot or exported .sr/.csv of the full transaction with decoded bytes (9F, then EF xx 16). The id[] values as read. The measured SCK frequency and duty cycle. The SCK level at the /CS falling edge (should be low for Mode 0). A zoomed image showing MISO changing after a falling edge. Board, part marking, VDD and wire length as above. If the ID differs from the table, record that too; do not correct it.
- **글에 넣을 위치:** '코드 — W25Q32JV JEDEC ID 읽기' section, right after the expected-ID table (L121-126). Add one sentence plus the capture image ('이 보드에서 읽은 값'), and note the environment line (board, part marking, wiring length, VDD, analyzer). The zoomed MISO-edge image can also back the L41 claim that DO changes on the falling edge.
- **오르는 항목:** C: moves the post from procedure-with-expected-values (3-1 cap, C ≤ 9) to 'observed result with environment' (8-11 band, no cap). A: first-hand evidence that the DO-on-falling-edge reading (L41) holds on real hardware.

## 2. Read-integrity sweep across dividers BR=010/001/000 (10.5/21/42 MHz), with the flash's real SCK→MISO delay measured at the MCU pin. This checks the post's central verdict: 42 MHz fails the read budget and 21 MHz passes up to 11.3 ns of round trip.

- **준비:** Same board and wiring as item 1; record the length again because it drives the round-trip delay. An oscilloscope with ≥ 500 MHz bandwidth and short-ground probes on PA5 (SCK) and PA6 (MISO) at the MCU pins, plus a probe at the flash CLK pin if reachable. Note probe model and bandwidth. The flash is pre-programmed with a known 1 KiB pseudo-random pattern (programmed once at BR=010 and verified there). OSPEEDR=10 as in the post. PCLK2 confirmed at 84 MHz.
- **절차:** 1) For each BR in {010, 001, 000}: run the 03h 1 KiB read N times (e.g. N = 10,000) and compare against the pattern; count bad bytes and bad reads. Also read JEDEC ID N times. 2) At each BR, use the scope to measure from the SCK falling edge at the MCU pin to the MISO transition at the MCU pin (round trip + tCLQV as seen by the MCU), and measure the SCK low time at the MCU pin. 3) Optional: repeat at 42 MHz with a longer wire or with OSPEEDR=11 to show the trend. Say whether the board is room temperature, and give the VDD.
- **기록할 것:** A table with one row per BR: SCK frequency measured, SCK low time measured (ns), SCK↓→MISO-valid at MCU pin (ns), remaining setup time vs tsu(MI) 6.5 ns, bad reads / N, bad bytes / total. Scope screenshots of the SCK/MISO edge pair at 21 and 42 MHz. Wire length, VDD, temperature. If 42 MHz reads clean (likely on a single board at room temperature, since datasheet values are worst-case max/min), record that and note it in the post as 'passes on this board but has no guarantee by datasheet'. Do not hide it.
- **글에 넣을 위치:** 'SCK 상한' section after the read-budget table and the L76 verdict paragraph: a short '이 보드에서 측정' table and one paragraph contrasting the datasheet verdict (worst case) with the observed margin (one board, typical conditions). This also gives the L161 summary a measured basis.
- **오르는 항목:** C: 12-15 band material (real measurement, the gap between datasheet worst case and one board's behavior, a trade-off and environment difference) instead of derivation only. A: an author-specific result no datasheet repost has (the measured round-trip delay and the actual failure or pass point), which strengthens the 'MISO timing binds before fSCK' conclusion beyond arithmetic.

## 3. Measured transfer time of one 1 KiB 03h read at 10.5 and 21 MHz, polling vs DMA, against the post's lower bounds (783.2 µs / 391.6 µs).

- **준비:** Same board. DWT->CYCCNT enabled (record HCLK). Logic analyzer on /CS and SCK. A polling build using the post's spi_xfer, and a DMA build (DMA2 SPI1 RX/TX streams with a TX dummy-byte stream, as L137 describes). Record compiler and optimization level (-O0 vs -O2 changes the polling gaps).
- **절차:** 1) For each SCK (BR=010, 001) and each method (polling, DMA): read 1 KiB with 03h, timestamping with CYCCNT around cs_low()...cs_high(). 2) Capture the /CS low width on the analyzer, and measure the idle gap between bytes on SCK (time with SCK stopped between consecutive 8-clock bursts). 3) Repeat for, say, 100 reads and take min/median/max.
- **기록할 것:** A table with SCK × method → /CS low width (µs, analyzer), CYCCNT time (µs), inter-byte gap (ns), effective throughput (MB/s), and percent of the SCK/8 bound. Analyzer screenshots showing the inter-byte gap for polling vs DMA. Compiler, -O level, HCLK.
- **글에 넣을 위치:** '전송 시간 하한' section: add measured columns (or a second table) next to the 783.2/391.6 µs bound table at L132-135, and change the DMA paragraph (L137) from a claim to an observation (whether DMA closes the inter-byte gap on this board and what is left).
- **오르는 항목:** C: replaces the 'lower bound only' numbers with observed results and a trade-off (polling gap vs DMA), which is the 12-15 band. A: a first-hand result that tests the L162 summary ('DMA changes CPU load, not the bound') rather than just asserting it.

## 4. Reproduced failure: a mode mismatch (Mode 1 and/or Mode 2) on the real flash, with the wrong ID it produces and the capture that diagnoses it.
