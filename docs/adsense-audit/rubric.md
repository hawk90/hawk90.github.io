# AdSense 공개 글 평가 루브릭

> 버전: 1.1
> 작성일: 2026-10-10  
> 대상: `draft: true`가 아닌 공개 글 약 726편  
> 목적: 공개 글을 `유지 / 보강 / 병합 / 제외 검토`로 일관되게 분류하기 위한 내부 평가 기준

## 1. 원칙

Google은 AdSense 승인에 필요한 글 수, 단어 수, 방문자 수, 운영 기간의 고정된 기준을 공개하지 않는다. 이 문서의 점수는 Google의 공식 점수가 아니라 여러 글을 같은 기준으로 비교하기 위한 내부 triage 점수다.

판정 우선순위는 다음과 같다.

1. Google 공식 정책 위반 여부
2. 사용자에게 제공하는 고유한 가치
3. 페이지 간 중복과 사이트 전체의 반복 패턴
4. 읽기·탐색·신뢰 경험
5. 보강 비용과 기대 효과

분량만으로 낮은 점수를 주지 않는다. 코드, 표, 로그, 다이어그램이 핵심인 기술 글은 산문 분량과 별도로 설명의 정확성·맥락·재현성을 평가한다.

평가는 분석과 보고서 작성으로 끝낸다. 각 루프는 `분석 → 분류·근거 기록 → 빌드·정책 검사 → 보고서 갱신`으로 완료한다. 원문 수정은 별도 승인된 수정 루프에서만 수행한다.

초기 루프 보고서는 기계 신호를 이용한 우선순위 분류로 시작했지만, 현재 루프-01~16은 원문을 읽은 뒤 글별 잠정 점수와 A~G 세부 점수를 기록한 상태다. 이 점수는 Google의 공식 점수나 합격 확률이 아니다. 루프 보고서의 `정성 검토 우선`, `근거·실전성 검토`, `1차 유지 후보` 같은 기계 분류와 요약 문서의 `1차 보강`, `2차 보강`, `검증 후 유지`는 작업 순서를 위한 내부 분류이며 최종 공개 판정과 구분한다.

향후 별도 원문 수정 루프를 시작할 때 적용할 안전 규칙:

- 존재하지 않는 측정값, 보드 환경, 테스트 결과, 운영 경험을 만들어 넣지 않는다.
- 근거 없는 보편 기준은 삭제하거나 `데이터시트·인터페이스 명세 확인`으로 바꾼다.
- 재현 가능한 측정·검증 절차를 추가할 수는 있지만, 실행하지 않은 결과를 실행한 것처럼 쓰지 않는다.
- 공통 템플릿을 반복 확장하지 말고, 각 글의 독립적인 질문·실패 조건·선택 기준을 강화한다.
- 보강해도 독립 가치가 부족하면 병합·draft 전환 후보로 남긴다.
- URL, frontmatter 날짜, seriesOrder, 기존 내부 링크는 별도 결정 없이 바꾸지 않는다.

## 2. 근거 수준

모든 판단에는 근거 수준과 구체적인 증거를 함께 기록한다.

| 태그 | 의미 | 사용 방법 |
| --- | --- | --- |
| `P0` | 정책 차단 가능성 | 발견 즉시 수정·제외·병합 검토. 총점보다 우선한다. |
| `P1` | Google 공식 품질·검색 기준 | 점수에 직접 반영한다. |
| `P2` | 기술·UX·신뢰 품질 기준 | 점수에 반영하되 적용 여부를 확인한다. |
| `P3` | 공개 승인 사례에서 반복된 실무 신호 | 참고 점수로만 사용한다. 공식 보장으로 표현하지 않는다. |
| `OBS` | 저장소·빌드·렌더링으로 확인한 사실 | 추측과 분리해 기록한다. |
| `INF` | 분석자의 추론 | 추론임을 표시하고 원문 근거를 남긴다. |

## 3. 즉시 차단·우선 조치 항목

다음 항목은 점수 계산 전에 확인한다. 해당하면 `P0`로 표시하고 최종 판정을 `우선 조치`로 둔다.

- 다른 사이트의 내용을 실질적인 추가 설명 없이 복사·재게시함
- 원문을 자동으로 치환하거나 요약한 수준이며 독자에게 새로운 가치가 거의 없음
- 검색어만 바꾼 doorway 또는 cookie-cutter 페이지
- 실제로 제공하지 않는 다운로드·서비스·자료를 약속함
- 사용자와 검색엔진에 서로 다른 콘텐츠를 보여주는 cloaking 또는 sneaky redirect
- 숨은 텍스트, 키워드 반복, 조작적인 구조화 데이터
- 광고가 메뉴·다운로드·본문 링크처럼 오해되도록 배치됨
- 비콘텐츠 페이지, 광고만을 위한 페이지, 빈 페이지에 광고가 노출됨
- 댓글·사용자 입력 영역에 관리되지 않는 스팸·성인·도박·악성 링크가 남아 있음

정책 의심은 단정하지 말고 `정책 확인 필요`로 기록한다. 에이전트는 외부 자료와 유사하다는 이유만으로 스크랩 판정을 내리지 않는다.

## 4. 100점 평가표

### A. 독창성·추가 가치 — 25점 (`P1`)

| 점수 | 기준 |
| ---: | --- |
| 0~5 | 공식 문서·검색 결과를 거의 반복하며 작성자의 설명이나 해석이 없음 |
| 6~12 | 설명은 있으나 일반론 중심이고 다른 사이트와의 차이가 약함 |
| 13~19 | 독자적인 구조, 예제, 비교, 문제 해결 관점이 확인됨 |
| 20~25 | 작성자의 전문 지식·분석·실패 사례·선택 기준이 뚜렷함 |

확인 질문:

- 이 글만의 주장, 관점, 예제, 비교, 결과가 있는가?
- 외부 자료를 사용했다면 전문 지식, 개선점, 리뷰, 개인 의견을 추가했는가?
- 독자가 이 글을 읽고 다른 글과 구별되는 결론을 얻는가?

### B. 내용의 충분성·완결성 — 20점 (`P1`)

| 점수 | 기준 |
| ---: | --- |
| 0~4 | 제목·코드·짧은 설명만 있고 문제와 결론이 없음 |
| 5~9 | 핵심 개념은 있으나 전제, 한계, 결과 중 일부가 빠짐 |
| 10~15 | 문제 정의부터 설명·예제·결론까지 기본 흐름이 완성됨 |
| 16~20 | 별도 검색 없이 핵심 질문을 해결하고 예외·한계·다음 단계까지 설명함 |

### C. 실전성·검증 가능성 — 15점 (`P1`, `P2`)

| 점수 | 기준 |
| ---: | --- |
| 0~3 | 실행·검증 방법이 없고 추상적인 설명만 있음 |
| 4~7 | 예제는 있으나 실행 조건이나 예상 결과가 부족함 |
| 8~11 | 재현 가능한 절차, 코드, 명령, 관찰 결과가 있음 |
| 12~15 | 실제 측정·실패·트레이드오프·환경 차이까지 기록되어 판단에 도움을 줌 |

단순히 `직접 테스트했다`는 표현만으로 점수를 올리지 않는다. 명령, 환경, 결과, 한계가 함께 있어야 한다.

### D. 중복·병합 위험 — 15점 (`P1`)

이 항목은 위험이 클수록 낮은 점수를 준다.

| 점수 | 기준 |
| ---: | --- |
| 15 | 독립된 질문과 결론을 가지며 다른 글과 역할이 분명함 |
| 10~14 | 공통 설명은 있으나 시리즈 내 역할이 구별됨 |
| 5~9 | 도입부·목차·예제·결론이 다른 글과 상당히 반복됨 |
| 1~4 | 제목만 다르고 핵심 내용이 거의 같거나 같은 질문을 여러 글이 나눠 답함 |
| 0 | 하나의 종합 글로 합치는 것이 사용자에게 명백히 더 유리함 |

비교 범위:

- 같은 시리즈 안의 인접 글
- 다른 시리즈의 동일 주제 글
- 제목·H2 구조·도입부·예제·결론의 반복
- 시리즈 허브에 두는 것이 더 적절한 공통 설명

키워드가 같다는 사실만으로 중복을 확정하지 않는다. 핵심 주장과 예제·결론을 직접 비교한다.

### E. 제목·검색 의도 일치 — 10점 (`P1`, `P2`)

| 점수 | 기준 |
| ---: | --- |
| 0~2 | 제목이 과장되거나 본문이 제목의 약속을 이행하지 않음 |
| 3~5 | 주제는 맞지만 독자가 얻는 결과가 불명확함 |
| 6~8 | 제목, 설명, 본문, 결론이 같은 질문을 향함 |
| 9~10 | 대상 독자와 해결하려는 구체적인 문제까지 명확하고 과장이 없음 |

### F. 탐색성·가독성·내부 연결 — 10점 (`P1`, `P2`)

| 점수 | 기준 |
| ---: | --- |
| 0~2 | 읽기 어렵거나 관련 글·시리즈에서 고립됨 |
| 3~5 | 기본 구조는 있으나 긴 글의 방향·다음 행동이 불명확함 |
| 6~8 | 목차, 제목 계층, 관련 글, 이전·다음 흐름이 기능함 |
| 9~10 | 모바일 포함 읽기 쉽고 현재 위치·전제 지식·다음 단계를 파악하기 쉬움 |

### G. 작성자·출처·신뢰성 — 5점 (`P1`, `P2`, `P3`)

| 점수 | 기준 |
| ---: | --- |
| 0~1 | 작성자, 출처, 업데이트 상태가 불명확함 |
| 2~3 | 작성자와 참고자료는 있으나 글의 주장과 연결이 약함 |
| 4 | 작성자·출처·버전·업데이트 상태가 대체로 명확함 |
| 5 | 작성자의 전문성, 1차 출처, 버전·환경, 수정 이력이 주장과 잘 연결됨 |

## 5. 최종 분류

| 총점 | 기본 분류 | 의미 |
| ---: | --- | --- |
| 80~100 | `유지` | 구조와 내용이 안정적. 필요한 경우 소규모 개선만 수행 |
| 60~79 | `보강` | 독창성·완결성·검증성 중 하나 이상 강화 |
| 40~59 | `병합 검토` | 독립 페이지로 유지할 이유를 확인하고 통합 여부 판단 |
| 0~39 | `제외 검토` | 보강 비용과 사용자 가치를 비교해 noindex·리다이렉트·비공개 검토 |

다음 조건은 총점보다 우선한다.

- `P0` 발견: `우선 조치`
- 동일 시리즈에서 3편 이상이 같은 문제를 보임: 개별 수정 전 시리즈 구조 재검토
- 중복 후보가 강하지만 독립적인 검색 의도가 있음: 병합하지 말고 차별화 보강 검토
- 짧지만 하나의 명확한 실전 문제를 완결하면: 분량만으로 제외하지 않음

## 5-1. 점수 산정 규칙

점수는 다음 순서로 기록한다.

1. 먼저 `P0` 정책 차단 가능성을 확인한다.
2. P0가 없으면 A~G 각 항목에 원문 근거 위치를 하나 이상 기록한다.
3. 각 항목 점수를 합산해 100점 만점의 내부 점수를 계산한다.
4. 총점 구간으로 기본 분류를 정하되, P0와 강한 중복 신호 같은 우선 조건을 함께 적용한다.
5. 근거가 부족한 항목은 추정으로 채우지 않고 `미산정`으로 남긴다. 모든 항목의 근거가 확보되기 전에는 총점을 `잠정`으로 표시한다.

점수 표에는 최소한 다음을 함께 기록한다. 기존 루프의 간결한 표 형식을 사용하더라도 아래 필드의 의미가 보고서에서 확인되어야 한다.

| 필드 | 의미 |
| --- | --- |
| `score_status` | `미산정` · `잠정` · `확정` |
| `score` | A~G 합계. 미산정 항목이 있으면 잠정 합계로 표시 |
| `evidence` | 점수의 근거가 있는 원문 위치·렌더링 위치·공식 출처 |
| `blockers` | P0/P1 우선 조치 및 확인 필요 항목 |
| `confidence` | 근거의 충분성: `낮음` · `중간` · `높음` |

이 점수는 Google이 제공하는 공식 AdSense 점수나 승인 확률이 아니다. 사이트 내부에서 검토 순서와 수정 우선순위를 정하기 위한 평가값이다.

## 6. 에이전트 출력 형식

각 에이전트는 점수만 반환하지 않고 다음 항목을 채운다.

    url: /blog/example/
    source_file: src/content/blog/example.md
    series: Example Series
    status: published
    decision: 유지 | 보강 | 병합 검토 | 제외 검토 | 우선 조치
    score_status: 미산정 | 잠정 | 확정
    score: 0
    confidence: 낮음 | 중간 | 높음
    blockers: []
    scores:
      originality: 0
      completeness: 0
      practical_validation: 0
      duplication: 0
      intent_alignment: 0
      usability: 0
      trust: 0
    evidence:
      - criterion: A
        level: P1
        excerpt_or_location: 본문의 구체적인 문단, heading, 코드 블록 또는 줄 번호
        reason: 왜 이 점수를 줬는지
    actions:
      - priority: P0 | P1 | P2 | P3
        action: 수정·보강·병합 시 필요한 작업
    uncertainties: []

필수 규칙:

- 원문 근거 없이 점수를 주지 않는다.
- `단어 수가 적다`만으로 thin content라고 판정하지 않는다.
- 공식 기준과 공개 사례의 조언을 구분한다.
- 확인하지 못한 사실은 `불확실`로 기록한다.
- 실제 수정·삭제·병합은 종합 검토 단계에서만 수행한다.

현재 잠정 점수 결과에 대한 필수 커버리지:

- 대상 글마다 A~G 합계가 있어야 한다.
- 대상 글마다 A~G 합계와 항목별 점수의 합이 일치해야 한다.
- `score_status`는 원문 수정 전까지 `잠정`으로 둔다.
- 원문 heading·코드·표·렌더링 위치 중 하나 이상의 근거를 글별로 남긴다.
- 근거 위치를 아직 글별로 완전히 세분화하지 못한 경우 `confidence: 중간`과 `uncertainties`를 명시한다.
- P0가 없다는 결론도 글별 정책 확인 범위와 미확인 영역을 함께 기록한다.

원문 수정이 시작된 뒤에는 위 마지막 규칙을 다음처럼 적용한다. 개별 루프에서 승인된 보강만 수정하고, 삭제·병합·draft 전환은 시리즈 전체 검토와 URL 영향 분석을 마친 뒤 수행한다.

## 7. 루프 운영 절차

공개 글은 한 번에 전수 수정하지 않는다. 같은 시리즈의 10편 안팎을 하나의 루프로 처리한다.

1. 루프 대상 파일과 공개 상태를 고정한다.
2. 원문·렌더링·내부 링크·중복 후보를 분석한다.
3. 글별 점수와 근거를 보고서에 기록한다.
4. 원문 수정 없이 `npm run check`, 빌드, 링크·sitemap·광고 경계 검사를 실행한다.
5. 판정과 미해결 의문을 보고서에 기록한다.
6. 루프를 닫은 뒤 다음 10편으로 이동한다.

루프를 닫는 조건:

- 대상 글 수와 보고서 행 수가 일치함
- 각 글에 판정·근거·다음 조치가 있음
- 검사 대상과 보고서만 변경되며 원문은 변경하지 않음
- 정책 의심·중복·URL 변경 후보가 별도로 표시됨
- 자동 신호만으로 삭제한 글이 없음

## 8. 시리즈 보고서 형식

시리즈별 Markdown 보고서는 다음 순서를 따른다.

1. 시리즈 목적과 독자
2. 공개 글 수와 시리즈 전체 위험 요약
3. 글별 평가 표
4. 유지 글
5. 보강 우선순위
6. 병합 후보와 병합 근거
7. 제외 검토 후보와 대체 URL
8. 시리즈 허브 개선안
9. 에이전트 간 의견 차이
10. 최종 검토 대기 항목

에이전트는 시리즈별로 병렬 실행할 수 있지만, 모두 이 문서의 동일한 버전과 출력 형식을 사용해야 한다. 에이전트 결과를 받은 뒤 종합 에이전트가 충돌을 표시하고, 사람이 최종 승인하기 전에는 콘텐츠를 변경하지 않는다.

## 9. 사이트 전체 사전 제출 체크리스트

이 절의 항목은 글별 100점에 섞지 않는 사이트 전체 게이트다. 모든 글의 점수가 높아도 이 게이트를 통과하지 못하면 제출 전 조치가 필요하다.

### 게이트 기록 형식

| 필드 | 값 |
| --- | --- |
| `gate_status` | `미검사` · `통과` · `조건부 통과` · `실패` |
| `scope` | 검사한 URL·템플릿·페이지 유형·커밋 |
| `evidence` | 빌드 로그·렌더링 URL·스크린샷·검사 결과 |
| `owner` | 후속 조치 담당 |
| `next_action` | 실패 또는 조건부 통과를 해소할 작업 |

### 별도 사이트 게이트

- 작성자·About·Contact·Privacy·Cookie·광고 관련 안내가 실제 사이트 구현과 일치하는가
- 광고가 메뉴·다운로드·본문 링크·버튼으로 오인되지 않고, 비콘텐츠·관리·로그인 페이지에 노출되지 않는가
- 공개 글·draft·noindex·관리자 페이지의 sitemap·RSS·canonical·robots 경계가 일치하는가
- 대표 모바일·데스크톱 렌더링에서 본문·코드·내부 링크·광고 밀도가 정상인가
- 로그인 없이 주요 공개 글이 접근되고, 빈 페이지·깨진 링크·렌더링 오류가 없는가
- 빌드·anchor·search/page parity·distribution feed 검사가 모두 통과하는가

### 콘텐츠

- [ ] 공개 글이 특정 독자 질문에 답한다
- [ ] 글별로 고유한 설명·예제·비교·분석이 있다
- [ ] 코드 중심 글도 코드의 목적·환경·결과·한계를 설명한다
- [ ] 같은 주제를 다루는 글이 독립적인 역할을 가진다
- [ ] 얇거나 미완성인 글을 무리하게 공개하지 않는다

### 구조·UX

- [ ] 메뉴와 시리즈 탐색이 실제 목적에 맞게 작동한다
- [ ] 제목·설명·본문·결론이 같은 약속을 한다
- [ ] 관련 글과 시리즈 허브가 고립된 글을 연결한다
- [ ] 모바일에서 본문과 코드가 읽힌다
- [ ] 깨진 링크·빈 페이지·오류 페이지가 없다

### 정책·광고

- [ ] 스크랩·자동 치환·doorway·keyword stuffing이 없다
- [ ] 광고가 메뉴·다운로드·본문 링크로 오해되지 않는다
- [ ] 비콘텐츠·유틸리티·관리 페이지에는 광고가 없다
- [ ] 사용자 댓글과 외부 링크가 관리된다
- [ ] 개인정보 처리와 광고 관련 안내가 실제 구현과 일치한다

### 기술·배포

- [ ] 공개 글만 sitemap과 RSS에 포함된다
- [ ] noindex 페이지가 sitemap에 제출되지 않는다
- [ ] canonical, robots, sitemap 경계 검사가 통과한다
- [ ] 주요 페이지가 로그인 없이 접근된다
- [ ] 빌드·링크·검색 인덱스·광고 배치 검사가 통과한다
