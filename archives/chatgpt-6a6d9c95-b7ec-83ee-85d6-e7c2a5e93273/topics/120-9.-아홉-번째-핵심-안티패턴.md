# 9. 아홉 번째 핵심 안티패턴

## Component Proliferation by Page Variation  
### 페이지 변형마다 컴포넌트가 증가함

블로그 기능이 늘면 다음이 생기기 쉽다.

```text
PostCard
FeaturedPostCard
CompactPostCard
SeriesPostCard
SearchPostCard
RelatedPostCard
TopicPostCard
LatestPostCard
```

처음에는 디자인 요구가 다르지만 점점 중복이 생긴다.

### 문제

- metadata 표시 규칙 불일치
- 어떤 카드에는 수정일, 다른 카드에는 작성일
- 태그 표시 개수 다름
- 접근성 label 다름
- 제목 줄 수 다름
- 수정 시 여러 컴포넌트 변경
- UI가 미묘하게 불일치

### 반대편 안티패턴

모든 것을 하나의 거대한 컴포넌트로 만들면 다음이 된다.

```astro
<PostCard
  featured
  compact
  horizontal
  showTags
  showDescription
  showSeries
  showReadingTime
  ...
/>
```

이것도 관리하기 어렵다.

### 권장

데이터 모델과 표현 primitive를 공유한다.

```text
PostMetadata
PostTitle
PostDescription
TopicBadge
ContentStatus
```

그리고 실제 layout은 몇 개만 둔다.

```text
ArticleCard
CompactArticleRow
FeaturedGuide
```
