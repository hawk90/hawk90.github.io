## `content-model.ts`

원본 Content Entry와 정제된 Domain Model을 분리한다.

```ts
export interface ContentDocument {
  id: string;
  slug: string;
  url: string;

  title: string;
  description: string;

  type: ContentType;
  status: ContentStatus;
  topicId: string;

  publishedAt: Date;
  updatedAt?: Date;
  lastVerifiedAt?: Date;

  headings: ContentHeading[];
  links: ContentLink[];

  prerequisites: string[];
  next: string[];
  related: string[];

  testedWith?: TestedEnvironment;
  supersededBy?: string;

  sourcePath: string;
  contentHash: string;
}
```

환경 모델은 너무 고정하지 않는다.

```ts
export interface TestedEnvironment {
  os?: string;
  kernel?: string;
  compiler?: string;
  hardware?: string;
  sdk?: string;
  toolchain?: string;
  notes?: string[];
}
```

CUDA 글에는 GPU와 CUDA 필드가 필요할 수 있고, Linux 분석 글에는 kernel source version만 필요할 수 있다.

처음부터 모든 도메인별 필드를 interface에 넣으면 모델이 커진다.

따라서 두 가지 선택지가 있다.

### 선택안 A: 공통 필드 + notes

단순하고 초기 운영에 적합하다.

### 선택안 B: 분야별 discriminated union

콘텐츠가 충분히 많아질 때 고려한다.

```ts
type TestedEnvironment =
  | CudaEnvironment
  | LinuxEnvironment
  | FpgaEnvironment;
```

초기에는 A가 낫다.
