# 6. 날짜 모델

JavaScript `Date`를 Domain 전체에 사용할지 ISO 문자열을 사용할지 결정해야 한다.

## 선택안 A. Domain에서 `Date`

```ts
publishedAt: Date;
updatedAt?: Date;
lastVerifiedAt?: Date;
```

### 장점

```text
정렬과 비교가 편함
날짜 연산이 쉬움
잘못된 날짜를 초기에 제거 가능
```

### 단점

```text
직렬화할 때 변환 필요
timezone 실수가 생길 수 있음
```

## 선택안 B. ISO 날짜 문자열

```ts
publishedAt: string;
```

### 장점

```text
JSON 직렬화가 단순
Manifest 저장이 쉬움
날짜 의미가 명확
```

### 단점

```text
매번 parse 필요
정렬 규칙이 코드에 반복될 수 있음
```

## 권장

Domain에서는 날짜만 필요한 경우 `YYYY-MM-DD` 문자열을 사용하는 것도 괜찮다.

```ts
export type IsoDate = `${number}-${number}-${number}`;
```

하지만 TypeScript template literal만으로 실제 날짜 유효성은 보장되지 않는다.

초기에는 입력에서 `Date`로 검증한 뒤 정규화 모델에는 ISO 문자열로 저장하는 방식이 실용적이다.

```ts
export interface ContentDates {
  published: string;
  updated?: string;
  lastVerified?: string;
}
```
