# 14. 열네 번째 핵심 안티패턴

## Audit Without Remediation Workflow  
### 문제를 발견하지만 수정 흐름이 없음

현재 audit 도구는 상당히 풍부하다. 그러나 감사 도구의 진짜 가치는 문제를 출력하는 것보다 **수정 우선순위와 흐름을 제공하는 것**에 있다.

예를 들어 다음 결과가 나왔다고 하자.

```text
깨진 내부 링크 172개
오래된 글 93개
이미지 없는 글 214개
중복 가능 주제 48개
```

그 자체로는 부담만 커진다.

### 필요한 구조

```text
severity
confidence
owner
suggested fix
automatic fixability
affected pages
priority score
```

예:

```text
ERROR
- 공개 링크 깨짐
- 빌드 차단

WARNING
- 오래된 버전
- 검토 필요

INFO
- 이미지 없음
- 선택 개선
```

### 반드시 피할 것

모든 audit 결과를 release blocker로 만드는 것.

그러면 결국 개발자가 audit를 끄거나 무시하게 된다.
