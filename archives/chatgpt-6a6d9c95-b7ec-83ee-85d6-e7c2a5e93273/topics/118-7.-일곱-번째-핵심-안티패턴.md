# 7. 일곱 번째 핵심 안티패턴

## Content Model Drift  
### 오래된 글마다 front matter 규칙이 달라짐

글이 수백 개 이상이면 콘텐츠 스키마가 반드시 변한다.

초기 글:

```yaml
title:
date:
tags:
```

최근 글:

```yaml
title:
description:
date:
updated:
series:
seriesOrder:
image:
draft:
```

앞으로는 다음이 추가될 수 있다.

```yaml
type:
topics:
difficulty:
status:
lastVerified:
prerequisites:
related:
```

### 문제

- 일부 글에는 description 없음
- 날짜 타입이 문자열과 Date 혼재
- 태그 대소문자 불일치
- 시리즈 이름 오타
- 순서 중복
- 이미지 경로 규칙 혼재
- 과거 글을 읽을 때 fallback 코드 증가
- 모든 컴포넌트가 optional field 처리

README의 기본 포스트 예시는 제목·날짜·설명·태그·시리즈·시리즈 순서를 사용한다. 폴더 구조가 URL 구조가 되는 방식도 명시되어 있다. citeturn214183view0

### 권장

콘텐츠 스키마에 버전 개념을 넣는 것이 좋다.

```yaml
schemaVersion: 2
```

다만 모든 글에 직접 넣기보다 migration 도구가 현재 스키마를 보장하도록 해도 된다.

### 최소 필요 사항

- 단일 schema 정의
- migration script
- deprecated field 목록
- fallback 종료 일정
- 콘텐츠 validation
- 일괄 수정 dry-run

중요한 원칙은 다음이다.
