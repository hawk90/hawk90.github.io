# 0. 실행 원칙

## 원칙 1. 콘텐츠 구조가 도구보다 먼저

다음 순서를 지킨다.

```text
대표 문서 선정
→ Topic 관계 확정
→ metadata 적용
→ UI 구현
→ 자동화
```

관계 기준도 없이 지식 그래프나 추천 시스템부터 만들지 않는다.

## 원칙 2. URL은 가장 늦게 변경

제목, 설명, Topic, UI는 비교적 쉽게 바꿀 수 있지만 URL 변경은 외부 링크와 검색 기록에 영향을 준다.

따라서:

```text
기존 URL 유지
→ canonical 문서 확정
→ 필요할 때만 redirect
```

순서로 진행한다.

## 원칙 3. 기계적 변경과 의미 변경 분리

예:

```text
Commit 1: type/status 필드 자동 추가
Commit 2: 대표 문서 상태 수동 검토
Commit 3: 본문 기술 내용 보완
```

한 commit에 섞지 않는다.

## 원칙 4. 현재 문제를 먼저 측정

다음은 추측으로 바로 최적화하지 않는다.

```text
검색 인덱스 크기
빌드 Peak RSS
코드 블록 수
색인 가능한 URL 수
얕은 태그 수
고아 문서 수
```

먼저 baseline을 만든다.
