# 4. `src/content`: 원본 문서 저장소

Astro Content Collections를 유지한다면 이 영역은 원본 Markdown·MDX를 담는다.

```text
src/content/
├── articles/
├── pages/
└── config.ts
```

## `articles/`

기술 문서 본문.

```text
src/content/articles/
├── pcie/
├── firmware/
├── linux/
├── cuda/
├── cpp/
└── archive/
```

다만 폴더가 public URL이나 Topic의 source of truth가 되어서는 안 된다.

예를 들어:

```text
src/content/articles/pcie/bar-sizing.md
```

가 있다고 해서 자동으로:

```text
topic = pcie-cxl
url = /pcie/bar-sizing/
```

가 되는 구조는 피한다.

파일 경로는 저장 편의를 위한 것이다.

문서의 정체성은 metadata가 담당한다.

```yaml
id: pcie-bar-sizing
slug: pcie-bar-sizing
topic: pcie-cxl
```

---

## `pages/`

About, Privacy, Editorial Policy처럼 일반 기술 문서와 성격이 다른 정적 페이지.

```text
src/content/pages/
├── about.md
├── privacy.md
├── editorial-policy.md
└── contact.md
```

이를 일반 Article Collection에 넣지 않는 이유는 다음과 같다.

```text
검색 ranking이 다름
RSS 포함 여부가 다름
Content Type 모델이 다름
광고 정책이 다름
날짜와 검증 상태가 다름
```
