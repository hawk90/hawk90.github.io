# 11. 구현 세부사항을 테스트

예:

```ts
expect(
  internalMap.size
).toBe(5);
```

실제 계약이 아니라 현재 구현 방식을 고정한다.

Map을 배열이나 다른 Index로 바꾸면 기능이 동일해도 테스트가 실패한다.

권장:

```text
입력
→ 공개 함수 호출
→ 관찰 가능한 결과
```

를 테스트한다.

예:

```ts
expect(
  manifest.byId.get("pcie-bar")
).toEqual(document);
```

이것도 내부 구조 계약이 공개 API라면 괜찮지만, 함수 내부 임시 Map까지 검사하지 않는다.
