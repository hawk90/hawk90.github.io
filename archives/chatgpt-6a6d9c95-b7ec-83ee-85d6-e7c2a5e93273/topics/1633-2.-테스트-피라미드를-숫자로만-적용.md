# 2. 테스트 피라미드를 숫자로만 적용

일반적인 조언은 다음과 같다.

```text
Unit 많이
Integration 중간
E2E 적게
```

하지만 기술 콘텐츠 사이트에서는 단순 비율보다 **계약의 위치**가 중요하다.

예를 들어:

```text
Markdown Plugin이 Heading ID를 잘못 생성
```

하는 문제는 작은 Unit Test만으로 발견하기 어렵고, 브라우저까지 갈 필요도 없다.

실제 Markdown Fixture를 렌더링하는 Integration Test가 적합하다.

따라서 테스트 유형을 개수 목표로 운영하지 않는다.

```text
Unit 80%
E2E 10%
```

같은 숫자는 품질을 보장하지 않는다.
