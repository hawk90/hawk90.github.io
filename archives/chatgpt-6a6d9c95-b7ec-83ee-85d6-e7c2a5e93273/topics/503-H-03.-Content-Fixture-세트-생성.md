# H-03. Content Fixture 세트 생성

실제 전체 콘텐츠만으로 parser와 schema를 테스트하면 edge case를 재현하기 어렵다.

## 최소 fixture

```text
valid-guide.md
valid-debug-note.md
historical-post.md
invalid-status.md
missing-topic.md
duplicate-slug.md
broken-relation.md
korean-heading.md
long-code-block.md
raw-html.md
```

## fixture의 목적

각 파일은 하나 또는 소수의 동작만 재현한다.

예:

```yaml
---
title: Duplicate URL
slug: pcie-bar
status: current
type: concept
topic: pcie-cxl
---
```

다른 fixture와 동일 slug를 사용해 충돌을 검증한다.

## 피해야 할 것

- 실제 게시글 전체 복사
- fixture 자체가 수백 줄
- 여러 오류를 한 파일에 몰아넣기
- production 문서 변경에 따라 fixture도 계속 수정

## 완료 조건

- 주요 콘텐츠 타입 fixture 존재
- 실패해야 하는 fixture와 예상 오류 정의
- 한글·영문·특수문자 사례 포함
- parser 변경 시 빠르게 실행 가능
