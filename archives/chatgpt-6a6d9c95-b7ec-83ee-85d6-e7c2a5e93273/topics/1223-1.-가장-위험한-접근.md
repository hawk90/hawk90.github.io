# 1. 가장 위험한 접근

## 모든 글에 Metadata 일괄 추가

예:

```text
500개 글 전부에:

type
topic
status
description
lastVerified
relations

추가
```

자동으로 필드를 넣는 것 자체는 가능하다.

하지만 의미 있는 값까지 자동으로 결정하면 문제가 생긴다.

```text
제목에 CUDA 포함
→ gpu-cuda

오래된 글
→ historical

짧은 글
→ reference

최근 수정
→ current
```

이 분류는 상당수 틀릴 수 있다.

특히 다음은 기계적으로 판단하기 어렵다.

```text
현재도 유효한 오래된 Concept
최근 작성됐지만 검증되지 않은 글
짧지만 강한 Reference
길지만 중복된 일반론
특정 버전에서만 유효한 Debug Note
```

## 전체 본문 AI 재작성

다음 접근도 피해야 한다.

```text
모든 글을 AI로:
문체 통일
Heading 추가
FAQ 추가
요약 추가
Description 생성
```

문제는 단순한 문체가 아니다.

```text
기술적 오류가 새로 들어갈 수 있음
직접 경험과 AI 추론이 섞임
글마다 있던 개성이 사라짐
기존 URL 전체가 대규모로 변경됨
Diff 검토가 불가능해짐
```

AdSense를 위해 글의 분량과 형식만 늘리는 결과가 될 수도 있다.

---

## 전체 URL 재설계

폴더와 Topic을 정리하면서 URL도 함께 바꾸고 싶어질 수 있다.

예:

```text
/posts/2021/pcie-bar/
→ /topics/pcie-cxl/concepts/bar-sizing/
```

정보 구조상 보기 좋지만 외부 링크, 검색 기록, 북마크, 기존 공유 링크가 깨질 위험이 있다.

따라서 기본 원칙은:

```text
지식 구조는 바꾸되
기존 URL은 우선 유지한다.
```

이다.
