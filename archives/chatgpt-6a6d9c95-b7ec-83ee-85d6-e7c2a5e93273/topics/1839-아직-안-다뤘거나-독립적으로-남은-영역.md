# 아직 안 다뤘거나 독립적으로 남은 영역

실제로 남은 것은 많지 않다.

## 1. 보안·공개 정보·공급망 보안

일부 Secret과 내부 정보 이야기는 했지만, 하나의 독립 영역으로는 아직 정리하지 않았다.

다룰 수 있는 내용:

```text
GitHub Actions 공급망
Action SHA 고정
Dependency confusion
악성 Markdown·MDX
Raw HTML·iframe
CSP
외부 Script
GitHub Token 권한
Dependabot 보안
게시물 속 민감 정보
```

다만 개인 정적 블로그 기준으로 30~50개 정도면 충분하며, 100개짜리 장문으로 만들 필요는 없다.

---

## 2. 콘텐츠 라이선스·저작권·인용 정책

부분적으로만 언급했다.

독립적으로 남은 내용:

```text
코드 Snippet 라이선스
Linux Kernel·LLVM 코드 인용
Specification 캡처
책·강의 자료
외부 다이어그램
이미지 라이선스
AI 생성 이미지
Repository License와 글 License 분리
인용 길이
출처 표기
```

실제 기술 블로그에는 꽤 중요한 별도 영역이다.

---

## 3. Backup·보존·데이터 복구

배포 Rollback은 다뤘지만 **장기 보존**은 별개다.

```text
Repository 손실
GitHub 계정 문제
이미지·LFS
외부 Gist
Domain 만료
댓글 데이터
Analytics 의존
정적 Export
오프사이트 Backup
```

다만 Git 저장소 기반이라 범위는 작다.

---

## 4. RSS·구독·배포 채널 전략

RSS 생성 안정성은 언급했지만 콘텐츠 배포 전략은 거의 다루지 않았다.

```text
RSS 전체 본문 vs 요약
Topic별 Feed
Newsletter
GitHub Release
SNS 자동 게시
중복 게시
Canonical
독자 재방문
```

그러나 현재 AdSense와 사이트 구조 개선 우선순위보다 낮다.

---

## 5. 실제 측정과 개선 루프

Analytics 도구의 과잉은 말했지만, 어떤 지표로 사이트를 개선할지는 완전히 정리하지 않았다.

```text
검색 유입 Landing
두 번째 글 도달률
Topic Hub 이동
Zero-result 검색
대표 글 이탈
구판 진입
광고 페이지별 성과
```

다만 Analytics 태스크는 또 검색·Hub·내부 링크와 겹치기 쉽다.

실제로 데이터를 연결해 분석할 때만 가치가 크다.

---

## 6. 국제화·영문 콘텐츠

영어 비중과 `hreflang`을 짧게 언급했지만 독립적으로 다루지 않았다.

```text
한영 URL
번역 콘텐츠
Canonical
용어 표기
코드와 설명 언어
자동 번역
영문 독자 대상
```

현재 영어 콘텐츠를 본격적으로 늘릴 계획이 없다면 생략해도 된다.

---

## 7. 실제 코드베이스 기준 감사

이게 가장 중요한 남은 작업이다.

지금까지는 거의 전부 **보편적인 안티패턴 카탈로그**였다.

아직 하지 않은 것은:

```text
실제 hawk90.github.io Repository
package.json
Astro Config
Directory
Content Schema
Markdown Pipeline
CSS
GitHub Actions
생성 URL
실제 페이지
```

를 보고 다음을 구분하는 일이다.

```text
실제로 존재하는 문제
잠재적 문제
현재는 해당 없음
이미 잘하고 있는 부분
```

일반론은 이제 충분해서, 다음 단계부터는 실제 코드 없이 계속하면 중복 가능성이 매우 높다.
