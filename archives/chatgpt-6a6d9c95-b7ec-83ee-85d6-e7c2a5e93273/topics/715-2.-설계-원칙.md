# 2. 설계 원칙

## 원칙 1. 원본과 정규화 모델을 분리한다

Astro의 raw entry를 사이트 전체에 전달하지 않는다.

```ts
CollectionEntry<"articles">
```

는 Astro에 종속된 입력 모델이다.

사이트 내부에서는 다음 모델을 사용한다.

```ts
ContentDocument
```

---

## 원칙 2. 형식 검증과 의미 검증을 분리한다

### 형식 검증

문서 하나만 보고 판단할 수 있다.

```text
status 값이 올바른가
날짜 형식이 맞는가
title이 비어 있지 않은가
```

### 의미 검증

전체 문서 집합이 필요하다.

```text
ID가 중복되는가
relation 대상이 존재하는가
superseded cycle이 있는가
Featured 문서가 current인가
```

---

## 원칙 3. Publication Policy는 사실만 결정한다

정책은 다음을 결정한다.

```text
렌더링할 것인가
검색엔진 색인을 허용할 것인가
검색 인덱스에 넣을 것인가
Sitemap에 넣을 것인가
RSS에 넣을 것인가
Featured가 될 수 있는가
광고 대상이 될 수 있는가
```

다음은 정책에서 결정하지 않는다.

```text
홈 카드 몇 번째인가
어떤 색으로 표시할 것인가
최근 글 6개에 들어가는가
카드가 2열인가 3열인가
```

이런 것은 Query와 UI의 역할이다.
