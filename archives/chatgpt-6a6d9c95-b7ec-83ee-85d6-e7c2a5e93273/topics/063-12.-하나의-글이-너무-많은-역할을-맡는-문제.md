# 12. 하나의 글이 너무 많은 역할을 맡는 문제

## Mega-Article

예를 들어 한 글에서:

- CXL 개요
- 프로토콜
- 장치 유형
- Linux 드라이버
- 메모리 할당
- 장애 분석
- 성능 측정

을 모두 설명하면 대표 가이드처럼 보이지만 유지보수가 어려워진다.

### Mega-Article의 문제

- 특정 정보를 다시 찾기 어렵다.
- 일부만 오래되어도 전체 문서가 낡아 보인다.
- 검색 의도가 너무 넓어진다.
- 수정 범위가 커진다.
- 초보자와 전문가를 동시에 만족시키기 어렵다.

### 반대 안티패턴도 있음

## Fragmentation by Default

한 개념을 지나치게 잘게 나누는 것 역시 문제다.

```text
CXL이란?
CXL.io란?
CXL.cache란?
CXL.mem이란?
CXL Type 1이란?
```

각 글이 몇 문단뿐이라면 독자는 계속 페이지를 이동해야 한다.

### 적절한 구조

```text
대표 Guide
├── 핵심 개념을 하나의 흐름으로 설명
├── 세부 문서 링크
└── 장애·실험·레퍼런스는 별도 문서
```

즉:

> 개념은 적당히 묶고, 독립적인 문제와 실험은 분리한다.
