## 검사 포인트

- QEMU CXL Type 3 에뮬레이션 글은 노트북 환경에서 실제 재현 가능한 명령·버전·검증 결과가 있는지 확인한다.
- Linux CXL 드라이버 글은 `cxl_pci`, `cxl_core`, region, DAX 계층 설명이 실제 커널 버전과 연결되는지 확인한다.
- 두 글 모두 CXL 표준·Linux 커널·QEMU의 빠른 변경 영향을 받으므로, 작성 시점·버전·지원 범위를 명확히 하는지 확인한다.
- 외부 링크가 없다는 자동 신호만으로 출처 부재를 확정하지 않고, CXL 공식 자료·QEMU 문서·Linux 커널 문서가 인용 또는 명시되는지 확인한다.
- 에뮬레이션 동작, region 생성, DAX 사용 가능 여부와 같은 주장은 환경 조건과 관찰 결과를 함께 기록한다.
- Abseil·Folly와 달리 Modern Embedded Recipes는 이 단계에서 일괄 제외하지 않는다.

### 공통 근거와 보강 우선순위

- 두 글 모두 단순 개념 설명을 넘어 명령, 검증 순서, 실패 조건을 제공해 현재 루프에서 가장 강한 실전성을 보인다. 공개 유지 후보로 분류한다.
- `part11-16`은 QEMU 실행 명령과 `lspci`·sysfs·`cxl list`·NUMA 확인 순서가 명확하다. 다만 QEMU 릴리스, 게스트 배포판·커널, `cxl-cli`/`daxctl` 버전을 고정하고 실제 성공 출력 또는 대표 실패 출력을 첨부하면 재현성이 더 높아진다.
- `part11-17`은 증상별 진단 경로가 독립적인 문제 해결 가치를 만든다. `drivers/cxl/`의 커널 버전별 함수·모듈 순서·errno 의미는 변할 수 있으므로 기준 커밋 또는 공식 Linux 문서 출처를 명시해야 한다.
- CXL 표준·QEMU 문서·Linux 커널 ABI에 기대는 주장은 현재 본문 내 설명만으로도 흐름은 이해되지만, 공식 URL과 확인 날짜를 보강하면 신뢰/출처 점수를 올릴 수 있다.
- 두 글은 서로 중복되지 않는다. 하나는 QEMU 기반 환경 구축, 다른 하나는 Linux 드라이버 장애 진단이므로 병합 대상이 아니다.
- 이번 평가는 점수 산정만 수행했다. 원문 수정·비공개·삭제·URL 변경은 하지 않았다.

### 시리즈 공통 문제

루프 16은 2편이라 이 루프 안에서 3편 기준을 채우는 문제는 없다. 루프 15의 `part11-15-pcie-to-cxl.md`와 함께 CXL 세 편을 보면 다음 문제가 3편 모두에 있다.

- 다른 시리즈와 핵심 내용이 겹친다(D 3~6): `part11-15-pcie-to-cxl.md` ↔ `performance-engineering/part3-11-cxl-interconnect.md`, `part11-16-qemu-cxl-emulation.md` ↔ `hardware/cxl/chapter12-qemu-emulation.md`, `part11-17-linux-cxl-driver.md` ↔ `hardware/cxl/chapter11-linux-driver.md`·`tools/debugging/kernel/chapter08-cxl-driver-debug.md`. 개별 보강 전에 Modern Embedded Recipes의 CXL 세 편을 CXL 4.0 Internals의 입구로 둘지, 병합할지 시리즈 단위로 정해야 한다.
