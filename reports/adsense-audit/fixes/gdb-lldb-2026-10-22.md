# GDB·LLDB 12편 수정 기록

기준일은 2026-10-22입니다. 범위는 `src/content/blog/tools/debugging/gdb-lldb/chapter01`부터 `chapter12`까지입니다. 기존 작업 트리 수정은 보존하고 평가 리포트 `published-loop-25.md`(Ch 1–2)와 `published-loop-26.md`(Ch 3–12), fix queue의 해당 `evaluationReport` 항목을 대조했습니다. 정책상 `published-loop*`, `published-scores*`, `published-summary.md`는 수정하지 않았습니다.

Ch 1의 debugger/플랫폼 비교, Ch 3의 문자 출력, Ch 4의 frame 설명, Ch 5의 watchpoint·hardware 자원, Ch 6의 Linux TID·mutex 소유자·scheduler locking, Ch 7의 core 생성과 제목·description, Ch 8의 RSP 패킷 표기와 trap 명령, Ch 10의 DAP·dashboard·Cortex-Debug 설명, Ch 12의 DWARF 예시·도구 주장을 바로잡았습니다. Ch 9와 Ch 11은 기존 제한·환경 구분을 보존하고 전체 본문과 예제 범위를 다시 확인했습니다. 공개 URL·날짜·draft 상태·seriesOrder는 그대로 유지했습니다. title/description에서 본문이 다루지 않는 `gcore`·`gdb -c`를 제거하고 실제 범위에 맞게 수동 정정한 예외는 Ch 7입니다.

재채점은 하지 않습니다. A~G 벡터·합계·factcheck 판정은 기존 평가 원장에 보존하고, 전체 수정 이후에만 다시 평가합니다.

## 검증 기록

- `node scripts/verify-gdb-lldb-examples.mjs`: Ch 8의 `rsp-check.mjs` 코드 fence를 문서에서 직접 추출해 Node로 실행했고 통과했습니다. Ch 1의 `hello.c` fence도 직접 추출해 `clang -g -O0`로 빌드했습니다.
- LLDB batch session: factorial 진입 breakpoint에서 `n = 5`와 thread backtrace를 확인하고 breakpoint를 해제한 뒤 `5! = 120`으로 정상 종료했습니다. sandbox에서는 process launch가 `no such process`로 거부됐고, 승인된 sandbox 외 실행에서 통과했습니다.
- GDB는 설치되지 않아 실행하지 않았습니다. RSP checker는 ASCII framing의 정상·부정 사례만 확인합니다. gdbserver·OpenOCD·J-Link·실물 보드는 실행하지 않았습니다. 이 미실행 범위는 PASS로 처리하지 않았습니다.
- `scripts/verify-gdb-lldb-examples.mjs`의 실행 로그는 같은 디렉터리의 `.log`에 기록했습니다.
- 최종 원문12편에 publish gate와inline math를 실행해 blocking0·수식오류0을 확인했습니다. [실행 로그](gdb-lldb-2026-10-22.log)와[gate 로그](gdb-lldb-2026-10-22-gate.log)를 참조합니다. 전체 site build는 이 작업 범위가 아니며 별도 담당입니다.

## 잔여 위험

모든 명령·제품·DWARF 주장을 현행 GDB/LLDB·OS·컴파일러·remote stub에서 전수 검증하지 않았습니다. 특히 macOS core dump, target별 RSP feature, GDB Python ABI, hardware breakpoint/watchpoint 자원은 실제 target과 toolchain에 따라 달라집니다. 실제 보드·원격 서버, GDB, 모바일 렌더링, 전체 site build는 확인하지 않았습니다. 따라서 문서의 예시 출력·환경 의존 주장은 이를 명시한 부분 외에는 실행 기록으로 읽으면 안 됩니다.

통합 단계에서 parent가 새 점수·A~G 벡터를 담은 임시 절을 제거했다. 이 수정 보고서는 재채점 결과가 아니며 `rescored:false`다. 공식 점수 원장44개는 기존baseline SHA와모두동일하다.
