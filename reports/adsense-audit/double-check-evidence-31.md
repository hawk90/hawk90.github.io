## factcheck 분류

- 원문 내부에서 재현되는 모순: ch07의 0x11 bit 해석과 0x10 필드 순번, memory ch01의 같은 NUMA 출력 블록 수치 모순.
- 기존 보고서의 내부 근거 인용 오류: ch05 kgdb conflict는 102행이 아닌 실제 QEMU의 50·60~64와 실하드웨어 102행을 함께 봐도 보고서 서술처럼 “같은 tty 공유가 충돌”이라고 결론낼 수 없다. 50행은 ttyS1 debug/ttyS0 console로 오히려 분리한다. `kgdboc`와 console을 같은 포트로 둔 102행의 지원 여부는 외부 문서 질문으로 남김.
- 내부에서 확정 불가한 외부/API 의심: eBPF verifier 상한·crash guarantee, kgdboc 포트 동작, drgn API, x86 error_code 정의, CXL API/version, Linux memory accounting, allocator API/defaults.
- 조건/예시 범위 차이로 factcheck 오류로 올리지 않은 것: ch07과 ch06의 분석 목적, ch01 PID 값의 다른 예시, heaptrack/allocator overhead 숫자, jemalloc 반올림, glibc large free chunk와 mmap threshold, CXL live/postmortem 관측.
