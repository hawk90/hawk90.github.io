# 공개 글 수정 진행

갱신: 2026-10-24T10:16:48.294Z. 대상은 Modern Embedded Recipes를 제외한 공개 글 **406편**이다.

현재 원문 SHA와 수정 기록이 일치하는 글은 **406편**, 아직 이 조건을 충족하지 않은 글은 **0편**이다. 실제 외부 분석 도구 실행 대기 6편은 기록 수에 포함하고, unassessed 0편은 제외한다.

점수·A–G·판정·factcheck 원장은 보존한다. 전체 수정 후에만 재채점한다. 기록 일치는 모든 기술 주장·하드웨어 동작의 검증 완료를 뜻하지 않는다. 각 보고서의 실행 범위와 NOT RUN 항목이 우선한다.

## 이어서 할 작업

챕터마다 원문 전문·기존 평가·1차 자료 대조 → 확인 오류 수정 → 가능한 정상/실패 예제 검증 → 근거 8필드와 SHA 기록 순서로 반복한다. 다음 장을 진행할 때 이미 끝난 배치의 상태를 덮어쓰지 않는다.

현재 배정과 미확인 항목의 다음 질문은 [전체 수정 큐](fix-queue.md)에서 관리한다. 단순 배정·정적 gate 통과만으로 수정 완료에 넣지 않는다. 실제 Valgrind 5편과 py-spy 1편의 도구 검증, 그 밖의 Linux/보드/IRQ/FP/성능 측정 등은 해당 기록의 한계를 따른다.

## 공통 검증과 과거 기록

- [기존 점수 요약](published-summary.md): 수정 전 평가 정본이며 수정 진행률과 별개다.
- [2026-10-21 공통 검증](fixes/repair-loops-final-2026-10-21.md), [2026-10-22 공통 검증](fixes/repair-loops-final-2026-10-22.md): 당시 완료 배치의 실행 범위.
- 후속 전체 사이트 build·anchor·reading 결과는 `fixes/repair-continuation-checkpoint-*-2026-10-22*` 로그에 checkpoint별로 보존한다. 이후 수정까지 소급해 통과했다고 해석하지 않는다.

집계는 `node scripts/track-article-repair-queue.mjs --apply`로 현재 파일과 고정된 수정 기록을 대조해 갱신한다. 커밋·push·배포 여부는 이 집계에 포함하지 않는다.
