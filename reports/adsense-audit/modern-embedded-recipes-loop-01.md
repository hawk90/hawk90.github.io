## 결론

이번 루프의 10편은 모두 독자가 이해하기 쉬운 문제 상황과 일관된 기술 설명 구조를 갖고 있다. 특히 각 글에 `어떤 상황에서 쓰나`, `측정 / 비교`, `자주 보는 함정`, `정리`가 있어 단순 API 목록보다는 실전 지향성이 보인다.

반면 다음 공통 위험이 있다.

- 9개 본문 글이 거의 동일한 8개 섹션 템플릿을 사용한다.
- 9개 본문 글에서 공개 외부 출처 URL이 추출되지 않았다. 내부 관련 링크와 출처 표기는 별도 확인이 필요하다.
- 본문 산문은 7편이 2,500자 미만이다. Google의 공식 분량 기준은 아니지만, 코드·표를 제외한 설명만으로 독창성과 완결성이 충분한지 검토해야 한다.
- UART·SPI·I2C·PWM 글은 실전 신호가 상대적으로 약하다. 실제 보드·계측기·파형·실패 조건이 있는지 확인해야 한다.

따라서 이번 루프의 기본 판정은 `보강`이며, 허브인 `00-preface`는 독립 글이 아니라 시리즈 안내 페이지로 `유지`하는 것이 적절하다. 현재 단계에서 draft 전환이나 삭제를 결정할 근거는 부족하다.

## 공통 평가

### 강점

- 제목이 다루는 하드웨어·신호 주제가 본문과 대체로 일치한다.
- `어떤 상황에서 쓰나`가 있어 초보적인 정의만 나열하지 않고 사용 맥락을 제시한다.
- `측정 / 비교`와 `자주 보는 함정`은 AdSense의 “사용자가 다시 방문할 이유”를 만들 수 있는 좋은 골격이다.
- 코드보다 산문이 짧지 않아 코드만 던지는 형태는 아니다.
- 시리즈 전체에서 디지털 신호 → 인터페이스 → 변환기 → PWM으로 이어지는 학습 흐름이 자연스럽다.

### 보강해야 할 공통 요소

- 보드·MCU·측정 장비·클럭 조건·전원 조건을 글마다 구체화한다.
- “측정 / 비교” 절에는 실제 측정값이나 최소한 재현 가능한 측정 절차를 넣는다.
- UART·SPI·I2C의 설명은 서로 겹치므로, 각 버스의 선택 기준과 실패 파형을 차별화한다.
- 외부 1차 자료를 연결하되, 링크를 추가하는 것만으로 독창성이 생긴다고 보지 않는다. 자료를 어떻게 해석했는지가 본문에 있어야 한다.
- 공통 설명은 시리즈 허브로 옮기고, 개별 글에는 해당 주제만의 판단 기준을 남긴다.

## 점수 해석

예비 점수의 합계는 A~G 100점 기준을 유지했다. 낮은 점수의 주된 원인은 글자 수 자체가 아니라 다음 세 가지다.

1. 실전 조건과 측정 결과가 일반적인 설명보다 약함
2. 외부 1차 자료와 작성자의 해석 연결이 확인되지 않음
3. 9편 모두 같은 구조라 시리즈 전체가 cookie-cutter처럼 보일 가능성

이 점수만으로 글을 삭제하지 않는다. 기술 글은 코드와 회로 설명 자체가 가치가 될 수 있으므로, 다음 루프에서 실제 예제·파형·수치·실패 조건을 확인한 뒤 점수를 확정한다.

### 공통 근거와 우선순위

- 이번 루프의 핵심 위험은 글자 수가 아니라 9편이 같은 템플릿을 사용하고, 외부 1차 출처·실제 측정값·보드 조건이 공통적으로 약하다는 점이다.
- UART·SPI·I2C·PWM은 설명만 늘리기보다 baud mismatch, CPOL/CPHA, stuck bus, dead-time 같은 실패 상황의 파형·로그·계산을 각각 넣어야 서로 다른 독립 가치를 만든다.
- ADC·DAC·clock 글은 ENOB, INL/DNL, jitter budget처럼 수치로 검증 가능한 항목을 최소 한 가지씩 제시하는 것이 우선이다.
- `00-preface`는 삭제 대상이 아니라 허브로 유지한다. 대신 공통 정의·환경 설명을 허브에 모으고 개별 글에는 주제별 판단 기준을 남기는 방향이 적절하다.
- 외부 링크를 추가하는 것만으로 점수를 올리지 않는다. 공식 자료를 어떤 설계 판단과 연결했는지 본문에서 설명해야 한다.
- 이번 평가는 점수 기록만 수행했다. 원문 수정·비공개·삭제·URL 변경은 하지 않았다.

### 시리즈 공통 문제

- 틀린 "더 깊이" 링크: 라벨은 특정 주제 글(I/O 측정, SysTick, GPIO 토글 측정, ISR latency, DMA throughput, Bus 통계, ADC 신호 처리, 신호 처리, Timer subsystem)인데 대상은 모두 자매 시리즈의 `00-preface`다. 해당: `part1-01`(129행), `part1-02`(149행), `part1-03`(173행), `part1-04`(167행), `part1-05`(164행), `part1-06`(190행), `part1-07`(180행), `part1-08`(175행), `part1-09`(161행). 9편 모두 F가 5점에 묶였다.
- 같은 H2 뼈대: 본문 9편이 모두 `한 줄 요약 / 어떤 상황에서 쓰나 / 핵심 개념 / 코드 / 측정 / 비교 / 자주 보는 함정 / 정리 / 관련 항목` 순서다. 글마다 예제는 달라 글 단위 P0로 보지 않았지만, 사이트 게이트(루브릭 9절)의 scaled content 수치에 넣어야 한다. 해당: `part1-01`~`part1-09`.
- 측정 표가 측정이 아니다: 칸을 "데이터시트 확인"·"부품별 상이"로 비웠거나(`part1-01` 30~35·51~56행, `part1-02` 107~112행), 출처·조건 없는 수치로 채웠다(`part1-03` 125~130행, `part1-04` 116~128행, `part1-05` 64~69행, `part1-07` 134~139행, `part1-08` 125~137행). 00-preface 356행의 집필 원칙 "측정 수치 포함"과 어긋난다.
- 제목 키워드 미이행: `part1-01`(Setup/Hold 없음), `part1-02`(MMCM 없음), `part1-07`(Pipelined 없음), `part1-06`(Arbitration 한 문장).
- 원문 안의 수치·설명 모순: `part1-04`(51행), `part1-05`(35↔123행), `part1-07`(45↔138~139행), `part1-09`(37↔76행). 같은 시리즈에서 4편이라 개별 수정 전에 Part 1 전체의 숫자·코드 주석을 한 번에 대조하는 것이 낫다.
- 본문 출처 0건과 STM32 계열 혼용: 9편 모두 G가 1점이다. 코드가 F4(84 MHz APB, `SR`/`DR`)와 H7·L4(`ISR`/`TDR`, FIFO)를 섞는다(`part1-04` 51·73·88행, `part1-02` 41~55행 대 `part1-04` 88행).
- GPIO 전기 특성 설명의 3중 반복: OSPEEDR·drive strength·내부 풀업 30~50 kΩ·I2C 풀업 표가 `part1-01`(45~58행), `part1-03`(62~75, 125~138행), `part1-06`(59~72, 141~143행)에 나뉘어 있다. 같은 rise time 표가 1-01에서는 "데이터시트 확인", 1-03에서는 "약 5~100 ns"로 서로 다르다.
