## 6. 정정 — I-15 사이드바 뎁스

사용자가 "사이드바에서 고르다 보면 시리즈 URL로 간다"고 지적해 다시 쟀고, **I-15의 `accepted` 판단을 뒤집었습니다.**

처음 판단은 *목적지 두 개*를 비교했습니다. "카테고리 페이지와 시리즈 페이지가 같은 글을 보여주지만 시리즈 쪽이 더 풍부하니 부가 잡음이다." 빠진 건 **거기로 데려가는 사이드바 행 두 개**였습니다. 독자가 중복을 만나는 곳은 목적지가 아니라 트리입니다.

### 트리가 실제로 하던 일

레벨 2가 세 가지 다른 일을 동시에 하고 있었습니다.

| 노드 | 하위 | 직속 시리즈 | 이 층이 하는 일 |
|---|---:|---:|---|
| programming | 1 | 0 | 통과만. 부모·자식이 같은 168편 |
| embedded | 4 | **7** | 하위 카테고리와 시리즈가 같은 깊이에 섞임 |
| embedded/hardware | 0 | 3 | 진짜 묶음 |
| embedded/protocols · rtos · riscv | 0 | **각 1** | 시리즈 이름만 바꾼 행 |
| tools | 3 | 0 | 통과만 |
| tools/debugging | 0 | 10 | 진짜 묶음 |
| tools/build | 0 | 2 | 진짜 묶음 |
| tools/emulation | 0 | **1** | 시리즈 이름만 바꾼 행 |

중복은 **4쌍이 아니라 5쌍**이었습니다. `programming` = `programming/code-review`(168편)를 세지 않았습니다.

그리고 두 종류의 행이 **같은 들여쓰기·같은 세로선·같은 클래스**(`CategoryTreeNode.astro`의 `childListClass`)를 공유해, 차이는 셰브론 유무뿐이었습니다. 하위 카테고리인 줄 알고 누르면 `/series/`로 가는 게 당연합니다.

### 고친 방법 — 분류 체계가 아니라 렌더 규칙

`categories.ts`를 건드리지 않았습니다. 그 파일은 드래프트를 포함한 **전체 코퍼스**를 서술하고, `programming` = `code-review`는 *오늘 무엇이 발행돼 있는가*에 대한 사실입니다. 분류를 오늘 상태에 맞추면 형제 글이 하나 올라가는 순간 틀립니다.

1. **단독 시리즈 접기** — 하위가 없고 시리즈가 1개인 가지는 시리즈 행을 지웁니다. 카테고리 행이 곧 그 시리즈입니다.
2. **통과 층 접기** — 직속 시리즈가 없고 하위가 1개면 한 행으로 합칩니다 (`Programming / Code Review`).
3. **시리즈 행 구분** — 목록 글리프를 붙여 카테고리 행과 눈으로 구분되게 했습니다.
4. **죽은 셰브론 제거** — 1·2번 적용 후 셰브론이 빈 곳을 여는 행이 4개 생겼습니다. AP-I-01에서 없앤 것과 같은 결함이라, 자식도 시리즈도 없는 노드는 디스클로저 컨트롤 없이 렌더합니다.

두 규칙 다 **발행 상태에서 유도**되므로 저절로 풀립니다. `embedded/rtos`에 두 번째 시리즈가 올라오면 시리즈 행이 돌아옵니다.
